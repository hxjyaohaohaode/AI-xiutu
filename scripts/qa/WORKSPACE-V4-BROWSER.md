# V4 真实浏览器 CI

`workspace-v4.browser.mjs` 是隔离 CI 集成检查，不属于普通单元测试。它使用真实 Chromium、HTTP、密码认证、私有文件存储、PostgreSQL 以及产品组件，不注入演示数据到生产界面、不模拟 API 成功。

## 环境与入口

根工作流负责安装锁定的 `playwright`、Chromium 系统依赖和浏览器。原生 PostgreSQL 应使用一次性的测试数据库；脚本要求 `CI=true`、非 production，且数据库名包含 `test`，避免误指向正常站点。

```sh
CI=true TEST_DATABASE_URL=postgresql://.../xiutu_test \
  node --import tsx scripts/qa/workspace-v4.browser.mjs
```

可选环境变量：

| 变量                   | 默认                   | 含义                                                   |
| ---------------------- | ---------------------- | ------------------------------------------------------ |
| `BROWSER_WEB_PORT`     | `4178`                 | 本机同源 Vite 端口，1024–65535，严格占用，不自动换端口 |
| `BROWSER_ARTIFACT_DIR` | `artifacts/browser-v4` | 截图与 JSON 报告目录，默认被 Git 忽略                  |

无需另起 API 或网页服务。脚本创建临时私有存储，运行真实迁移，启动 API 的随机本机端口，再让 Vite 代理到该端口。结束后关闭浏览器、Vite、API 和数据库连接，删除临时私有文件。测试数据留在一次性测试数据库，由 CI 服务销毁；不要对复用的个人开发库运行。

脚本在导入供应商适配器前清空供应商密钥，并关闭真实功能开关，包括 `AI_ASSISTANT_ENABLED` 与 `AI_VOICE_ENABLED`。搜索使用 `input[type=search]` 对应的 `searchbox` 角色；四角鼠标操作先等待现有预览更新结束、再以无副作用的试定位等待把手稳定可操作；竞争租约用例先等待上个命令的浏览器回执和服务端租约释放，避免把正常异步阶段误判为失败。这些是脚本就绪条件，不会绕过产品权限或伪造响应。

两个测试账号使用脚本内存中的随机密码和产品的 scrypt 密码函数建立，通过真实 `/v1/auth/login` 校验密码并取得浏览器会话。预置 `phone_verified_at` 属于可信非生产测试夹具，不意味着短信实收、注册审核或手机号所有权得到验收。脚本不输出密码、会话 Cookie 或供应商密钥，也不保存网络 trace。

## 当前脚本覆盖

1. 在 320×700、390×844、844×390、1024×768、1440×960 真实 Chromium 视口中导入脚本生成的 600×400 RGBA 技术图，经用户控件设置负曝光，检查无横向页面溢出、照片未受 UI 模糊、当前主滑条在自身可见滚动区。
2. 手机检查面板底边紧贴底部工具带，默认停靠不盖住完整拟合照片；拖动到约 339px 后仍可使用主滑条；折叠/恢复不丢曝光，主动最大化可逆。
3. 通过下载入口读取实际配方文件；通过产品导出入口等待 PNG 下载，解码核对尺寸与像素确实改变，不只检查文件名或 PNG 字节不同。
4. 四角把手的 Alt+方向键 0.1px、真实鼠标拖动、Esc 取消和撤销。以导出的完整配方核对结果，不通过读取 React 内部状态假装操作。
5. 两个独立浏览器会话实际 HTTP 登录、选择同一团队项目和作品，检查在线会话、远端光标、确认后的参数同步、不同目标并发保留和撤销归属。
6. 为确定性冲突检查，以一个真实会话直接取得服务端租约，再通过另一个浏览器界面调整相同参数；要求 UI 显示冲突、远端版本不被覆盖，释放后通过明确“重试同步”提交。这里的竞争方租约由测试协议客户端取得，不冒称为另一只真实手指持续拖动。
7. 丢失保存响应：代理测试路由先让请求到达真实服务器并完成，再中断返回；重试必须收到同一幂等命令的回执，不能多生成版本。只有这条网络故障使用 Playwright route，未伪造后端成功响应。
8. 在真实素材界面写入个人长期说明，另一账号读取不到；真实用量账本包含正负测试调整，下载 CSV 并核查内容。
9. 收集未捕获浏览器运行错误；任一用例失败则整体非零退出，保留已完成与失败记录，不生成“全通过”结论。

### 六个固定公开照片工作流

另有 **3 张真实公开照片 × 390×844、1440×960 两个视口，共 6 个独立用例**。输入来自 `portrait-native-inputs.json` 中 Matplotlib 的 Grace Hopper 样本、Google MediaPipe 的 portrait、pose 样本。每次下载最多读取清单声明的字节数，HTTPS 请求限时 30 秒，不跟随重定向；原始字节数与 SHA-256 必须完全一致。原件只缓存于 Git 忽略的 `artifacts/browser-v4-source-cache`，后续轮次读缓存时仍重新核对大小与哈希。下载、解码或哈希不符会令本轮失败，不能跳过、使用不同照片或退回技术图。这些原字节不会加入 Git，也不会发送至 AI 供应商。

每个用例建立新的浏览器上下文，经真实文件输入导入 JPEG，展开明暗调节，记录初始中性状态，再依次通过曝光精确输入设置 **−3 EV、0 EV、+3 EV**，最后通过工作台快捷键撤销到 0 EV。初始、中性、负向、正向和撤销后五个状态均读取真实画布像素，并从产品导出窗口生成、下载和解码原分辨率 PNG；预览与导出分别检查变暗／变亮的方向、发生变化的像素数、亮度均值和透明度，不用滑条数值替代图像结果。回到中性及撤销后的 RGBA 哈希必须与初始／中性结果相同。最终另下载真实 V4 配方，核对曝光为 0，并保留文件。

这六个照片上下文显式采用 `reducedMotion: 'no-preference'`，并检查浏览器没有命中减弱动效媒体条件；控件点击等待 Playwright 的实际可操作性，读取画布前等待图像处理结束及两个动画帧。每个状态保留页面截图与导出的 PNG。报告记录原始下载哈希、实际解码／导出／预览尺寸、RGBA 哈希、亮度、裁切至纯黑／纯白的像素数以及实际变暗／变亮的像素数。精确输入用于获得可复现的 −3／0／+3 EV；原有技术图用例仍负责拖动、键盘细调、面板尺寸和透视手势。

## 证据与限制

输出 `report.json` 包含浏览器版本、用例状态、实际 DOM 测量、下载尺寸、照片像素证据、失败原因和开始/结束时间。`photo-*-export.png` 是从产品下载取得的图像；其余 `photo-*.png` 为页面截图，`photo-*-recipe.json` 为实际下载的配方内容。截图用于后续人工检查，但自动几何断言不能替代视觉配重判断。报告固定标明 `manualVisualReview=false`。

本脚本未覆盖原生 iOS/Android、真实软键盘/多指硬件、整日断线恢复、200MP 原片的所有格式、外部短信、真实付费图片模型、真实双向语音质量或美颜效果的人工评价。技术图用于坐标、处理和数据链路验证；三个公开照片流程验证不同内容与画幅的导入、双向曝光、撤销和导出链路，不执行人物识别，也不构成人像美颜质量验收。正常动效下的可操作性等待不等于人工评判运动路径和视觉配重。本轮受限本地环境未实际运行此脚本；只有对应新提交的 GitHub CI 结果能证明其在 CI 中执行情况。不得将 `node --check` 或 V3 的浏览器截图写成 V4 实操通过。
