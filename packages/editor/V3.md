# Recipe v3：精细构图、区域联动、绘制与合成

`schemaVersion: 3` / `engineVersion: '3.0.0'` 是新的显式算法协议。v1/v2 的解析与数值解释器保持原语义；升级必须调用 `migrateRecipeToV3`。所有新增阶段中性时，迁移后的输出与原配方逐字节相同。试图把 v3 传给 `migrateRecipeToV2` 会失败，不会丢掉新增操作。

## 公共入口

```ts
import {
  createRecipeV3,
  createAdjustmentRegionV3,
  createColorBlockV3,
  parseEditorRecipe,
  migrateRecipeToV3,
  renderEditorRecipeTiled,
  compileEditorCoordinateMap,
  getEditorParameter,
  setEditorParameter,
} from '@ai-xiutu/editor';

const recipe = createRecipeV3({
  transform: { rotationDegrees: 2.35, perspectiveY: -4.2, fit: 'crop' },
  optics: { denoiseChroma: 18 },
  regionEdits: [
    createAdjustmentRegionV3({
      id: 'subject-left',
      name: '左侧人物',
      color: {
        curves: {
          red: [
            [0, 0],
            [0.5, 0.56],
            [1, 1],
          ],
        },
        hsl: { orange: { saturation: -8 } },
      },
    }),
  ],
});

const result = renderEditorRecipeTiled(source, recipe, {
  maxPixels: 4_194_304,
  tileSize: 256,
  images: new Map(), // 如有 imageLayers，每个 sourceId 必须由可信调用者解析
});
const coordinates = compileEditorCoordinateMap(source, recipe, originalPreview);
coordinates.toSource({ x: 0.5, y: 0.5 }); // 构图框架坐标
coordinates.toContent({ x: 0.5, y: 0.5 }); // 加上液化后的实际原图取样位置
```

- `parseRecipeV3` / `validateRecipeV3` 校验持久化对象，不补缺失字段。
- `createRecipeV3` / `createColorBlockV3` 深度合并白名单结构，数组整体替换。
- `createAdjustmentRegionV3` 为新区域补齐全部色彩块；不同 mask discriminant 整体替换。
- `getEditorParameter` / `setEditorParameter` 仅接受注册数值路径，保存所有其他字段；不知道的路径明确失败。
- `parseEditorRecipe` / `renderEditorRecipe` / `renderEditorRecipeTiled` 自动按三个明确版本分派。
- 不提供脚本字段、不读取 URL、不在图像内核访问数据库或网络。

## 配方字段和阶段顺序

v3 保留 v2 的 `adjustments/curves/geometry/local/levels/hsl/grading/detail/effects/regions`；旧局部区域仍先按 v2 执行。新增字段：

| 字段           | 内容                                                        |
| -------------- | ----------------------------------------------------------- |
| `transform`    | 精细旋转、水平/垂直透视、双轴剪切、双轴缩放、位移、画幅适配 |
| `optics`       | 明度降噪、色度降噪、红/蓝通道径向色散及中心                 |
| `regionGroups` | 一组共享色彩修正；成员交叠处只执行一次                      |
| `regionEdits`  | 各区域完整色彩块、独立蒙版、强度及可选组身份                |
| `imageLayers`  | 调用者解析的图像层、定位/缩放/旋转/镜像、混合/强度/蒙版     |
| `paintLayers`  | 隔离绘制层；颜色、画笔、擦除和冻结源仿制                    |
| `warp`         | 手动推移/收缩/膨胀/旋转位移场、背景保护蒙版                 |

执行顺序固定为：**完整旧 v2 色彩阶段（暂不执行旧几何）→ 全局 optics → 按顺序组色彩 → 按顺序独立区域色彩 → 图像图层 → 绘制图层 → 位移场 → 旧整数裁切/90°旋转/镜像 → 精细仿射/投影**。

当新增源空间阶段全部不活动时，直接用旧 v2 路径再执行精细构图，保证中性迁移字节不变。区域色彩、optics、图层和几何之间明确存在 RGBA8 量化边界；不宣称整个 v3 流水线都是无损浮点/HDR。

### 区域与联动

`ColorBlockV3` 包含 13 项基础调整、4 路曲线、色阶、8 色段连续权重 HSL、三路分级、纹理/清晰度、褪色/黑白/颗粒/暗角和全部 optics。区域曲线与全局曲线使用相同的 2–16 控制点规则；其他范围复用已经发表的 v2 数值语义。

组共享修正先作用于所有已启用成员蒙版权重的 **max-union**：`max(mask_i × regionOpacity_i) × groupOpacity`。一个像素在两个成员中也只应用一次组修正。然后各成员仍可叠加自己的独立色彩。禁用一个组只停用共享色彩，成员的独立修正继续存在。

区域候选从当前阶段图像计算；原图颜色范围选区始终参照不可变源图，防止调色后选区漂移。蒙版权重为 0 的像素逐字节保留。局部锐化/降噪会读取邻域，蒙版限制写入范围，并非“任何运算都不能读取区域外像素”。

v3 的 `SelectionMaskV3` 兼容六种 v2 蒙版，并增加复合蒙版：

| 操作         | 连续权重定义       |
| ------------ | ------------------ |
| union        | 最大值             |
| intersection | 最小值             |
| subtract     | 依次 `a × (1 − b)` |
| xor          | 依次 `a + b − 2ab` |

反选只在原图范围内有效。复合层次、节点数、长画笔和栅格游程均有公开上限，不能递归构造无界表达式。

### 自由构图与坐标

精细旋转 ±180°、透视/双轴剪切 ±60°，显示步长 0.01°；独立缩放 0.1–4 倍，步长 0.001；位移为裁切后宽高的归一比例。验证器接受范围内任意有限精度，不要求用户只能取滑杆步长的整数倍。

精细矩阵依次为居中 → 缩放 → 双轴剪切 → 平面透视 → 旋转 → 位移。平面透视采用固定距离的投影模型，不能从二维照片恢复真实三维结构。接近奇异的剪切组合、穿越投影地平线的组合和超预算输出会明确拒绝。`fit: 'contain'` 包含所有变换后的角点；`fit: 'crop'` 保留原裁切画幅并允许内容越界。contain 中整体位移会被边界重定位抵消，位移控制应在保留画幅模式使用。

几何渲染与交互共享同一个 3×3 矩阵及逆矩阵。精细变换用**线性光、预乘 alpha 的双线性重建**，背景透明，透明像素的隐藏 RGB 不污染可见边缘。恒等和旧 90° 置换有无重采样路径；缩放不是超分辨率模型，强缩小仍可能混叠。

`getEditorOutputDimensions` / `mapEditorSourceToOutput` / `mapEditorOutputToSource` 是框架几何。位移场改变内容取样，因而提供额外 `mapEditorOutputToContent`。频繁指针操作应 `compileEditorCoordinateMap` 一次并复用回调，避免每个 pointermove 重新校验整份配方。裁切与液化笔触使用框架坐标；液化后按所见内容选择原图像素，应使用 `toContent`。液化后的复杂蒙版浮层必须使用同位移场渲染，单纯移动椭圆轮廓不代表精确逆形变。

### 明度/色彩降噪与色散

降噪是独立的、可测试的 5×5 边缘加权参考算法：空间权重 `[1,4,6,4,1]` 的外积，以编码亮度差限制跨边缘混合，以 alpha 加权邻居。明度与色度残差分别混合，保留原 alpha；无人物检测、肤色分类或学习型重建承诺。

红/蓝通道色散各可设 ±20 原图像素，方向相反时就是反向径向位移；中心可独立设置。绿通道和 alpha 不变，边缘使用钳位采样。缩小预览的像素型邻域、颗粒与色散相对于预览像素计算，属于预览近似；100% 像素验收必须使用同分辨率输入。

### 绘制、仿制与混合

每个绘制层独立保存启用状态、强度、混合模式、可选蒙版和笔触。笔触有连续源坐标折线、短边归一半径、羽化、强度和 RGBA8 颜色。半像素硬边圆笔对齐像素中心时只影响一个像素。增加线段采样密度不会重复积累同一笔的强度。

- paint：在隔离层上涂色，RGBA alpha 与笔触强度相乘。
- erase：擦除当前绘制层，不擦掉底下的原始图像。
- clone：从本次绘制前的不可变画面，按显式起点偏移复制；后续笔触不会读取已画过的内容。它是仿制，不是自动痘痘检测、纹理修补或泊松融合。

画笔使用空间索引，减少长路径逐像素全扫描；隔离绘制缓冲为 tile 大小的 Float32 RGBA，最终层组合后写入 RGBA8。16 种混合模式实际使用不同方程：normal、multiply、screen、overlay、soft-light、hard-light、darken、lighten、difference、exclusion、color-dodge、color-burn、hue、saturation、color、luminosity。

混合数学参考 [W3C Compositing and Blending Level 1](https://www.w3.org/TR/compositing-1/)，本项目独立实现，色彩混合发生在编码 sRGB 域，alpha 采用 source-over。非分离模式使用该模型的亮度/饱和度定义；不能等同于任意厂商所有历史色彩配置下的结果。

### 图像合成

`imageLayers.sourceId` 是不可变资源标识，渲染器只接收调用者显式传入的 `ReadonlyMap<string, RGBAImage>`。缺少活动图层资源时失败，不下载任意 URL、不忽略缺图。服务端保存或加载配方必须重新验证**所有**引用，包括暂时禁用的图层；浏览器本地的临时 ID 不能被当作云端授权。

每层包含 x/y/width/height、独立角度、水平/垂直镜像、强度、混合模式和源空间蒙版。支持超出原图边界，当前画幅之外部分被裁去。当前图像层固定先于绘制层执行；没有声称已支持任意交错的 Photoshop 图层树、智能对象、文字排版或 PSD 往返。

### 液化与背景保护

4 种手动位移：push、pinch、bulge、twirl。每个操作有稳定 ID、中心/终点、半径、羽化和 −1…1 的有符号强度；负值反向，0 恒等。操作按反序建立目标到来源的取样映射，从冻结图像一次重采样，不是反复改写同一像素。

保护蒙版满权重的目标像素逐字节保留；羽化权重软化边界。单次推移距离最多按 0.8 半径计算，防止一次跳变把画面撕开；更大位移可用多次动作。该平滑手动场不是三维人体模型、物理变形约束或自动背景重建。重叠强变形可能改变纹理，不能保证每种极端设置都自然。

几何逆采样原则与 [OpenCV 几何变换说明](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html) 一致；项目未引入或复制 OpenCV 图像代码。

## 扩展追溯与安全

区域、图像层、绘制层、warp 操作可包含 `origin`：`moduleId/instanceId/parameterId/value`，及可选 ≤64 项数值 `parameters`。它只记录模块来源和用户控制值，不执行任何代码。人像模块可通过稳定 ID 替换已有修正，避免每拖动一次滑杆重复叠加新效果。

解析先作有界纯数据克隆：拒绝 getter、函数、Symbol、class 实例、循环、未知字段、非法原型、稀疏数组和非有限数字。版本、组引用、图层身份、蒙版预算、paint 总笔触/点数均严格校验。`origin` 不能绕过任何图像/模型/账号权限，模块也不能借它获取运行时能力。

## 公开预算与实测边界

| 项目                           | 当前限制                                                      |
| ------------------------------ | ------------------------------------------------------------- |
| v3 默认输入/输出预算           | 4,194,304 像素                                                |
| v3 显式输入/输出硬上限         | 16,777,216 像素；不是64MP                                     |
| 额外图像层总像素               | 按不同 sourceId 计数，≤33,554,432；各图仍受调用者单图预算约束 |
| 新区域 / 组                    | 12 / 6；旧 v2 8 区域另保留                                    |
| 绘制层 / 图像层                | 24 / 8                                                        |
| 绘制总笔触 / 总点数 / 单笔点数 | 128 / 8192 / 1024                                             |
| warp 操作                      | 128；超过 64 笔时，归一化半径的平方和不得超过 64              |
| 蒙版节点 / 嵌套深度            | 128 / 4                                                       |
| 蒙版画笔总点数 / 栅格总游程    | 8192 / 16384                                                  |
| paint 空间索引引用             | 全部活动笔触合计最多1,000,000；构建过程中即检查               |
| paint 预测扫描工作量           | ≤600,000,000 次段距离上界估计；超限明确提示拆分               |

笔触索引和预计工作量在图像大小的中间缓冲分配前检查；索引构建也响应取消，不在占满索引内存之后才拒绝。v3 tiled 限制了浮点中间工作缓冲，但源 RGBA、区域候选、合成、warp 与几何仍可能保留多个整图字节缓冲；clone 额外冻结一份输入。16MP 不代表所有手机都有足够内存，也不等于移动端性能保证。极大的区域数量、长笔触与重复邻域操作会变慢，应使用 Worker、任务代次和真实设备预算。同步渲染的 AbortSignal 只在读取时观察；要抢占同线程上的同步计算，终止 Worker。

已有独立回归包含：v1/v2 中性迁移字节一致、全部几何逆映射/奇异拒绝、透明边重建、复合选区、共享组交叠只执行一次、区域完整色彩、16 混合模式、逐像素paint、擦除与冻结clone、合成资源缺失、signed位移/保护、降噪/色散、full/tiled 多尺寸逐字节相同、真实 worker 输出一致、浮点缓冲尺寸及安全预算。最终数量和全仓库检查结果以本轮验证日志为准。
