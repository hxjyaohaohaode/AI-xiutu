# Recipe V4：自由透视、局部修复与独立质感算子

本版是 `schemaVersion: 4 / engineVersion: "4.0.0"` 的确定性 CPU 参考内核。真实新增内容是四角单应变换、谐和修复/梯度域补片、六种局部信号处理，以及它们与旧调色、蒙版、绘制、图层、液化的统一数据路径。它不是高位深或 200MP 浏览器编辑引擎；服务器媒体模块的母版与瓦片另见 [media README](../media/README.md)。

## 版本与公开入口

`EditorRecipe` 包含 v1/v2/v3/v4；`LayeredRecipe` 是 v3/v4。使用 `parseEditorRecipe` 做通用版本分发，或使用严格的 `parseRecipeV4`。后者拒绝未知字段、访问器/不安全对象、非有限数、重复新操作 ID、越界参数和超量蒙版。`createRecipeV4`、`validateRecipeV4`、`migrateRecipeToV4` 是构建、验证、迁移入口。

旧配方不会自动换算法。迁移只增加中性的 `projective/healing/retouch`，没有启用新空间处理且四角变换为单位变换时，直接调用原 v3 渲染路径，保留已有舍入、次序和像素结果。`migrateRecipeToV3` 拒绝丢弃 v4 字段。内部 `recipeV3Stage` 仅用于阶段编排，不能拿它保存成降级后的用户文档。

`renderEditorRecipe` / `renderEditorRecipeTiled` 自动分发；直接调用也有 `renderRecipeV4` / `renderRecipeV4Tiled`。输入、输出均为 sRGB RGBA8。`Float32Array`/`Float64Array` 中间计算不会把 8 位输入变成真实 16 位源素材。

工作台在源图符合设备导入预算且不超过 16,777,216 像素时，所有工具的交互和静止帧使用同一原尺寸工作栅格及原尺寸合成素材。点运算使用参考内核的字节编码，空间算子使用分块及局部缓存。旧版可导入的更大源图使用固定的工作代理，拖动过程保持同一来源和预算。下载始终按源像素执行参考配方。

## 字段与坐标契约

V4 保留 V3 全部字段，另外增加三个严格字段：

| 字段         | 含义                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| `projective` | `{enabled,corners:[TL,TR,BR,BL],fit:'contain'或'crop'}`；角点是目标位置 |
| `healing[]`  | 独立、有 ID 的修复操作，带蒙版、保护、源补片、强度、方法和迭代预算      |
| `retouch[]`  | 独立、有 ID 的质感区域，带蒙版、保护、半径与六种独立信号参数            |

所有 `mask`、`protection`、修复 donor `source` 仍使用**原始源图归一化坐标**。四角是例外：它们属于**完成旧裁切/翻转/90°旋转和 V3 精细变换后的 frame**，值为这个 frame 宽高的比例，而不是原图归一化坐标。角点顺序固定为左上、右上、右下、左下的逻辑对应，不按当前屏幕位置重新排序。

构建器：`createProjectiveTransformV4()`、`createHealingOperationV4(overrides)`、`createRetouchRegionV4(overrides)`。操作支持与 V3 相同的惰性 `origin` 追溯数据；内核不会把来源字段当脚本执行。完整类型以 `src/v4-types.ts` 为准。

## 真正四角投影与显示映射

`compileProjectiveTransformV4(preDimensions, projective)` 求解单位矩形到四边形的 8 自由度单应矩阵，返回 `matrix / inverse / dimensions / origin / identity`。这不是用三个角点估计的仿射变换。

- 各目标坐标有限且位于 `[-2,3]`；允许适度移到 frame 外。
- 必须是正向凸四边形；交叉、凹形、镜像、坍缩、过短边和穿过图像的正向投影地平线拒绝。镜像请用现有明确的翻转操作。
- `contain` 将目标包围盒平移到输出原点并扩展尺寸；纯平移在这种模式下会被包围盒拟合抵消，这是定义本身。需要在固定画布内摆放时选 `crop`。
- 旧 frame 的裁掉区域不能被四角变换“重新露出来”；每个中间 viewport 都参与裁切。输出像素在有效四边形之外为透明。
- 精细矩阵与四角矩阵合成后仅做一次线性光、预乘 alpha 的双线性重采样，避免连续两次重采样进一步损失。源图的旧整数裁切仍在前面。
- 有效凸四边形的**包围矩形空白处**可以包含逆映射地平线。V4 对这种空白像素跳过采样，不能让一个透明角落导致整张图失败；精细变换与四角串联时同样处理。

UI 应每次配方/源尺寸改变时编译一次 `compileEditorCoordinateMap(imageDimensions, recipe, original?)`，复用以下方法，不在每个像素或 pointermove 重新解析配方：

| 方法                     | 语义                                                                    |
| ------------------------ | ----------------------------------------------------------------------- |
| `dimensions`             | 最终整数输出尺寸                                                        |
| `containsOutput(point)`  | 输出归一化点是否落在所有几何裁切后的有效范围；与源 alpha 无关           |
| `toOutput(sourcePoint)`  | 源 frame 到显示 frame，适用于未液化控制几何；被裁掉的源点可能无有限投影 |
| `toSource(outputPoint)`  | 逆几何映射，不包含液化位移                                              |
| `toContent(outputPoint)` | 逆几何后再应用逆位移场，适用于最终图的取色/绘制定位                     |

先用 `containsOutput` 检查绘制命中，再检查 `toContent` 是否在原图内。不能把源 alpha 为零的像素一概视为不可绘制。对覆盖物的源点投影，调用方必须处理 `toOutput` 无法投影的点，不能用一个裁掉点的异常使整张 React 画布崩溃。

四角拖拽使用 `getEditorPreProjectiveDimensions` 及 `mapProjectiveOutputToCornerFrame / mapProjectiveCornerFrameToOutput`。这两个函数转换的是目标把手位置，所以只处理输出包围盒偏移和尺度，**不是** inverse-homography 的内容取样。

液化是艺术性局部位移，极端设置不保证数学可逆；`toOutput` 不伪造液化的前向解。编辑源坐标蒙版/保护范围时可采用明确标示的未液化 frame，最终绘制和取色用逆位移。

## 执行次序与联动

新空间操作启用时的顺序固定为：旧全局/区域调色、曲线及光学参数 → 修复 → 质感区域 → 图像图层 → 绘制图层 → 液化 → 旧整数构图 → 合成精细/四角变换。每一步的坐标都在源图 frame，最后才改变构图。区域组和复合蒙版沿用 V3 完整语义。

修复后的素材可以继续做妆容、绘制和液化；图层合成结果不会倒灌进此前的修复 donor。更换这一次序会改变旧作品，必须另起明确版本。保存应保存完整 Recipe，而不是把某个面板拥有的字段拼成新的残缺文档。

## 局部修复：独立版本的三种算法

`HealingOperationV4` 提供以下参数：

| 参数                | 范围/解释                                           |
| ------------------- | --------------------------------------------------- |
| `opacity`           | 0～1，最终修复与原像素混合                          |
| `mask / protection` | 完整 V3 复合蒙版；有效权重为选区 × (1−保护)         |
| `method`            | `diffusion`、`patch-poisson` 或显式 `exemplar-v1`    |
| `source`            | donor 中心，原图归一化 `[0,1]`；null 为有界邻域搜索 |
| `searchRadius`      | 原图短边的 0.001～2 倍；只影响自动找 donor          |
| `iterations`        | 1～512 的整数，是显式计算预算                       |
| `texture`           | 0～1 donor 梯度保持量；diffusion 不使用这个参数     |

`diffusion` 固定未选边界，在孔洞中求离散调和填充。适合平滑区域的小点状缺陷，不会理解被删物体后面的场景。

`patch-poisson` 使用目标边界约束和 donor 的拉普拉斯梯度，做红黑 Gauss–Seidel 松弛。它传递纹理梯度并补偿边界亮度，不是复制补片的绝对 RGB。`source=null` 时最多尝试四圈、每圈 24 个确定性候选，以边界残差、弱绝对色差和距离评分。候选选择不是语义识别或训练模型。

donor 不得覆盖未知修复区域；donor 及梯度所需邻域必须不透明。当前目标邻域也必须完全不透明。修复区域过大、远距离不连续蒙版造成包围盒过大、没有有效边界、找不到合格 donor、预算不足会明确失败，不降级成假成功。未选择/完全保护的字节与 alpha 保持原值，源输入不修改。

大面积物体移除、复杂重复纹理、文字、头发和身体结构可能留下平滑块或接缝。这些算法没有宣称达到商业 AI 消除质量。数学背景参考 [Pérez 等，Poisson Image Editing](https://www.cs.cornell.edu/courses/cs5670/2020sp/resources/Perez_PoissonImageEditing.pdf) 与 [OpenCV 梯度域克隆接口](https://docs.opencv.org/4.12.0/df/da0/group__photo__clone.html)；本实现是独立 TypeScript 代码，不调用 OpenCV，也不冒称实现 Telea 或 LaMa。

`exemplar-v1` 从原始阶段的已知不透明区域寻找实际补片，按已知边界与置信度推进填充前沿。`patchRadius` 为1～8，缺省4；`iterations` 在这种方法中控制有界搜索精度（至少16），而非 Poisson 松弛次数。搜索包含确定性粗搜索、局部细化与已选偏移复用；可以固定 donor 中心。采用有界通道亮度补偿，`texture` 控制 donor 残差保留。单次目标上限32,768像素，比较与复制共用134,217,728工作预算，超限/无供体/取消都明确失败，不输出部分结果。保护区、选区外部及 alpha 保持不变，透明 RGB 不作供体。

其设计参考[Criminisi 等的样本修复研究](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/tr-2003-84.pdf)，但使用本仓库独立的有界搜索与优先规则，并非论文完整复现或神经内容理解。周期纹理测试优于扩散填充；当前三张自然照片的小面积人工损伤样本中误差均未优于扩散，不能据此宣称新方法普遍更好。旧配方仍使用原方法，用户按纹理与接缝预览选择。

## 六种局部质感算子

`RetouchRegionV4` 的 `radius` 为短边的 `0.000001～0.1`，到采样时取至少 1 像素；其余效果在同一区域可组合，全部 0 是精确中性。

| 参数         | 范围      | 实际运算                                              |
| ------------ | --------- | ----------------------------------------------------- |
| `smoothing`  | 0～100    | 固定 5×5 稀疏空间采样、亮度保边权重，降低局部亮度波动 |
| `texture`    | −100～100 | 对高频残差做双向减弱/增强                             |
| `uniformity` | 0～100    | 平滑局部色度差，保留亮度项                            |
| `shine`      | 0～100    | 按亮度与邻域差压制高光肩部                            |
| `speckle`    | 0～100    | 3×3 中值差识别离散亮暗脉冲；不是痘痘识别模型          |
| `fineLines`  | 0～100    | 降低局部暗细线的亮度差；不会重新合成真实皮肤结构      |

这些算子处理 RGBA8 输入。负向纹理较强时会减弱自然肌理，正向纹理较强时会加强皱纹或噪声。

上表的5×5采样属于未带 `algorithm` 的已发布配方。`guided-v1` 使用 alpha 加权局部线性回归与两次均值传播，完整计算 2r 邻域。`guided-v2` 的统计权重为有效蒙版与 alpha 的乘积，排除保护区、透明像素及选区外颜色。主半径与约三分之一半径分别计算中尺度起伏及细部残差，平滑控制中尺度，带符号的纹理控制细部。色度、高光、脉冲和双侧较亮的暗线使用独立计算。RGB 变化接近色域边界时按同一比例缩放，保留变化方向。活动 ROI 上限 4MP，全部参数为 0 逐字节保持输入。

`guided-v3` 的细线计算同时检查法向亮度和切向连续性，在两个尺度判定。去反光同时检查局部增亮与相对去饱和，在线性 RGB 中有界扣除中性反光。当前新建的人像规划、手工质感区域和 Agent 质感候选采用 `guided-v4`，在此基础上把孤立明暗斑点和局部色度斑点分开，`chromaSpots` 范围为 0～100，默认 0；旧算法不接受这个参数。已保存的质感区域保留算法版本。导向滤波、尺度与反射分离用于设计对照，本项目实现有独立的采样与保护约束。 [He、Sun、Tang 导向滤波](https://kaiminghe.github.io/publications/eccv10guidedfilter.pdf) · [Lindeberg 边缘与脊线](https://www.csc.kth.se/cvap/abstracts/cvap191.html) · [Guo 等的单图反光分离](https://openaccess.thecvf.com/content_ECCV_2018/papers/Jie_Guo_Single_Image_Highlight_ECCV_2018_paper.pdf)

画笔与橡皮可在大于1px的数位笔模式下保存 `sampling.algorithm='swept-v1'`、逐点压力及断点。相邻采样点以变半径连续轨迹计算覆盖，同笔覆盖取最大值，4×4亚像素采样细化边缘。断点用于离开图像再返回，连续段之间不补线。1px硬边绘制仍走像素中心采样。协作笔画影响区计入抗锯齿外沿。压力与合并事件参考 [W3C Pointer Events](https://www.w3.org/TR/pointerevents4/#dom-pointerevent-pressure)。

## 连续流形变

新 V4 手动液化和新增人像精细部位使用 `algorithm:'flow-v2'`。固定方向的推移和沿半径的捏合、膨胀在一维轨迹上做 16 步 RK4 积分，旋转流沿用半径不变的解析解。网格索引按位移后的点继续查询此前笔触，多个笔触按原次序合成逆映射。已有未带字段的位移笔触和 `flow-v1` 继续按各自算法回放。

带 `resampling:'bounded-cubic-v1'` 的笔触使用线性光和预乘 alpha 三次重采样。把结果限制在邻域可见像素的通道范围内以控制振铃和透明边缘串色。整个复合位移场只采样一次，未被精细笔触影响的像素继续采用对应的既有取样路径。拖动时使用编辑预览的完整栅格，复用液化前的图层、局部调色和修复结果。追加笔触时保留历史笔触的已渲染结果，只在当前笔触作用范围内重新复合所有逆位移并从液化前的像素取样。

V3/V4 径向蒙版可单独设置 `rotationDegrees`（−180…180，源图像素顺时针）与 `shape`（`ellipse`、`rectangle`、`diamond`）。未提供字段时按原椭圆采样。区域计算可按实际范围裁出候选并保留图像滤镜的周边依赖。旋转、反选、羽化和分块在同一源图坐标下计算。

连续速度场积分的数学背景可见[Freifeld 等的图像变形研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC5889303/)；本实现是紧支撑径向场数值积分，不使用该论文的分片仿射求解器。测试检查正负极值、多种羽化下的采样 Jacobian 为正、反向积分恢复误差、原图/透明度/保护和分块一致性；任意硬边保护、多个极端操作叠加及解剖合理性仍需具体画面审查。数值测试不能保证所有用户配方都自然。

## 人像规划器与新执行器接口

`@ai-xiutu/portrait` 对 V4 保留 `projective/healing/retouch`，不因拖动人物滑条丢失新字段。旧 V3 primitive 仍保留原算法版本；用户在 V4 新调人物皮肤参数时才生成 `portrait.basic.v2` 的质感操作。磨皮、纹理、匀肤和细纹不再共享一个模糊参数。

`createPortraitPixelAdapter(driver)` 是供真实神经执行器替换/扩展的入口，校验模型版本、权重 SHA 与许可声明、源 RGBA 哈希、尺寸、蒙版、保护、取消和迟到结果，并在合成时保护外部像素及 alpha。本仓库没有借这个接口假装已经配置神经祛痘、3D 遮挡、头发重建或神经补光。

## 资源与取消边界

| 项目                          | 当前硬边界                                     |
| ----------------------------- | ---------------------------------------------- |
| 编辑源图和最终输出            | 各 16,777,216 像素；默认每次执行预算 4,194,304 |
| 新修复操作                    | 16 个                                          |
| 新质感区域                    | 12 个                                          |
| 两种新操作总蒙版节点          | 128；V3 蒙版仍遵循其独立原预算                 |
| 单次修复目标                  | 262,144 像素                                   |
| 单次修复包围盒                | 1,048,576 像素                                 |
| 配方修复包围盒像素 × 迭代总和 | 134,217,728                                    |
| 质感区域包围盒及累计目标      | 4,194,304 像素                                 |
| 已解析图像图层的累计像素      | 32MP；每个输入仍受本次预算约束                 |

`Tiled` 表示分块执行得到一致结果，不等于零整图缓冲。本版仍有完整 RGBA 阶段副本；16MP 单张 RGBA8 就有 64MiB，实际任务可能同时持有多个阶段与 ROI 数组。不能把常数升到 200MP 来宣称完成大图内存治理。

内循环按行/迭代检查取消，返回新数据，不修改原图。主线程同步 JS 无法在长循环中接收新的事件；浏览器应放 Worker 中并在需要时终止 Worker。任何新插件都必须说明自己的取消边界，不能仅靠一个 AbortSignal 字段宣称第三方计算可立即中断。
