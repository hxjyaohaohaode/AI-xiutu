# 可见、可撤回的编辑智能体与实时语音

本包实现 Responses 工具循环、模型协议档案、编辑候选与实时 PCM 协议。身份、数据库、额度、网络会话与持久发送证明由 `apps/api/src/assistant` 承担；图片生成仍使用既有 `packages/multimodal` 和 `packages/ai`，不被对话模型代替。

## 1. 实际入口与责任

| 入口                               | 责任                                           | 扩展约束                                                        |
| ---------------------------------- | ---------------------------------------------- | --------------------------------------------------------------- |
| `assistantModelConfigSchema`       | 模型是否启用、任务、服务点、输出/时长/委派预算 | 运营配置采用 CAS；不得将助手配置覆盖同 ID 图片配置              |
| `runEditorAgent`                   | 有界 Responses 循环、工具与来源、输出审核      | 固定官方 HTTPS；最多4轮，每轮最多8次工具调用；无自动付费重试    |
| `applyAssistantProposal`           | 将允许的全局/局部/分组参数编译为配方候选       | 数值范围来自编辑器；未知路径、重复路径、越界和无效目标拒绝      |
| `recipeHash`                       | 规范化配方的稳定身份                           | 不能以源图片相同代替当前版本/参数相同                           |
| `VOICE_MODELS` / `voiceStartEvent` | 精确语音 ID 与 Live/Realtime 独立协议          | 新协议须有首方来源、参数映射、协议测试，不能按名字猜            |
| `PcmResampler`                     | 连续采样重采样、跨包边界                       | 与浏览器 AudioWorklet 的真实 PCM 输出比较                       |
| `VoiceTranscriptBuffer`            | 按角色/条目/时间合并增量转录                   | 不在每个字前重复插入角色，不把半句丢掉                          |
| API `AssistantJournal`             | DB 标记与独立持久卷的派发证明                  | 新文件独占创建、fsync；未知结果不重发；不可删除日志解决启动错误 |

共享请求/事件 DTO 在 `packages/contracts/src/assistant.ts`、`assistant-ui.ts`、`memory.ts` 和 `creative.ts`。HTTP 与 WebSocket 路由见 [API_V4](../../apps/api/API_V4.md)。原始表结构为 schema v9；v11 增加执行授权与原子预算申领，v12 增加事件、上下文证据、工具档案与记忆版本，v13 绑定稳定会话根。已发布迁移不回写。

## 2. 从对话到修改

1. 用户选对话模型、参考素材、允许搜索的空间，以及是否允许公开搜索/个人长期标注。共享当前画面单独选择，默认不把照片发给模型。
2. API验证账号/当前项目/全部素材权限，将当前配方、作品版本、源图片与预览绑定。图像被实际解码并规范为最长边1024的JPEG后审核；它是编辑预览，不是原始200MP文件。
3. 额度预占时冻结配置。输入审核通过后，写数据库派发标记和独立磁盘证明；再验证当前权限、付费状态和模型启用状态，才发送请求。
4. 工具包括编辑器/素材查询、参数与曲线候选、组合编辑、生成草案、候选像素检查与选择、历史/大型工具结果回查、记忆建议和工作卡片。允许的公开检索使用官方 `web_search`；网页图不会自动下载或获许可。
5. 用户可选仅建议、预览确认（默认）、预算内自动执行。授权绑定本人、项目、模型、动作、点数、步骤和期限，服务端原子申领并可撤销。文本轮次和语音委派共用服务端保存事务，候选、不可变版本、预算申领与回执一起提交。未保存的本地基线、旧版本、他人占用、超预算或未选定的多个方案保留候选。以 `appliedRevisionId` 和真实版本确认保存。
6. 生图草案保持完整提示词与全部参考。跨项目引用先明确确认复制，经权限/配额检查后保留可追溯副本；中途失败保持原幂等键及已完成副本，不静默删图。候选决定成功后才带入生成面板。用户仍独立选择图片模型、尺寸、质量等参数，并确认费用。
7. 旧版本过期、成员离开、模型停用或结果不确定时，停止后续动作。拒绝候选不会自动退款已经完成的供应商调用。

所有编辑候选基于同一冻结配方；它们不是按返回顺序自动串行应用的操作。当前 `propose_curve` 为全局 RGB/红/绿/蓝曲线；区域参数使用既有区域/组 ID，不自动创建任意图层、任意脚本或人像身份。

`describe_editor`、`search_resources`、`read_history` 通过 MCP SDK 的会话内传输完成初始化、发现与调用。工具随授权范围注册，读取前后复核权限。文本、委派语音和云端检索分支复用同一工具服务。公开网络检索继续使用 OpenAI 的单独请求，只接收用户批准的字面查询。写入权限仍由作品 API 事务核验。[MCP 工具协议](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

Responses 和 Live / Realtime 目录公布按型号及快照核对的档案。运营端可查看项目实际返回的模型 ID。Responses 通过各型号档案验证推理、输出格式、采样和服务档位。实时语音可独立配置转写、输入降噪、轮次检测、语速及 Live 开场，委派走应用的授权和配额。具体协议、默认值和证据见 [OpenAI 模型与参数](../../docs/OPENAI-MODELS.md)。

`propose_retouch` 与 `propose_healing` 复用 V4 源坐标选区，可新增操作或设置已有手动操作的绝对强度。`operationId:null` 表示新增。既有 ID 必须属于相应集合并可手动修改。选区从 `regions/regionEdits/healing/retouch` 引用。额外保护区与既有保护区取并集。回调保留算法和手动供体。新质感操作采用 `guided-v4`，新增局部色斑参数 `chromaSpots`；既有旧算法区域不静默升级。修复支持 diffusion、patch-poisson 和 exemplar-v1。缺少合适选区时需先圈选。

`propose_sequence` 可在一个候选内组合调参、曲线、局部修复/质感和基础构图。步骤顺序组合配方状态，像素流水线仍固定为调色→修复→质感→图层→形变→构图，不能靠排列步骤改变这一顺序。`inspect_candidate` 在显式共享当前画面后，读取仍有权访问的原件及图层，通过同一个编辑器实际渲染前后画面，输出亮度、明暗截断、改变像素数与差值；经审核后的候选 JPEG 进入下一轮视觉输入。`select_candidate` 在收到该画面后才可选定它，同一轮先检查后选择会被拒绝。共享图片时自动保存必须有经过此检查的明确选择。

`propose_scene_balance` 仅在模型支持图像输入、用户实际共享当前画面且冻结配方与检查回调可用时提供。它读取服务端对实际配方渲染的亮度分位和通道余量，在 `balanced`、`open-shadows`、`retain-highlights`、`preserve-night` 四种策略下，以0–1强度产生全局曝光、阴影和高光增量；按注册表范围和步长量化，其余参数不变。有效像素不足、近全黑或没有有效增量时返回 `no_change`；夜景策略不自动提高曝光。它不能恢复已缺失的高光细节，也不代表天空、材质或三维光照识别。

任务分支的 `candidate`、`pixel-review`、`nomination` 节点通过 `dependsOn` 记录准备候选、实际像素复核和推荐的依赖关系。推荐只返回进入应用权限核验的提名，随后仍检查有效授权、成本、协作租约和冻结版本；图谱完成不等于作品已保存。沿用现有分支读取接口，不新增通用 MCP 服务、工具发现/执行端点或任意外部 skill 安装能力。

每轮最多三次检查；单进程最多两个 Worker，其中最多一个运行原尺寸检查。普通调参使用最长边512px代理、15秒期限。新增/改变局部修复或质感必须在原尺寸执行整套配方，30秒期限，源图/输出各16MP上限、全部图层合计16MP、压缩输入合计32MiB；沿用编辑器的更严格局部工作量和选区预算。提交给模型的JPEG仍缩至512px，统计使用实际原尺寸像素。`fullResolutionChecked` 与 `inspectedRecipeHash` 绑定候选；未共享、超时、无供体或超预算时不得自动保存新局部效果，候选保留以便用户审阅/缩小选区。Worker的192MiB V8旧生代限制不包含图像数组和原生解码缓冲，实际内存还受上述像素预算约束。这些检查不等于审美通过、HDR/高位深编辑或16MP手机性能承诺。

语音更新当前作品后，采纳按该候选的不可变基础版本解析素材。画布编辑立即作废旧上下文。新候选绑定通话上下文代数，应用前同时验证代数、作品头版本、保存基线哈希和当前权限。迟到回执用于结算，旧画面上的候选不会继续进入编辑。

## 3. 双向实时语音

上下文预算计算对每条冻结历史仅分词一次，归档后仅计算替换指针，不重复分词同一原文。原始用户约束、候选决定来源、预算清单和档案指针保持相同。`scripts/qa/assistant-latency.mjs` 以ABBA顺序逐项比较旧、新规划结果与耗时；这不缩减对用户要求的保留。

文本SSE在已接收的短回复没有标点、上游暂时没有新包时，增加250ms交付调度。保持同一个未完成的reader.read，避免计时器触发后重复读取导致丢包或乱序。仍需服务端审核通过才展示，保持16次增量上限、最终完整性比对、真实费用收据和未知结果不重试。250ms是调度期限，不是包含供应商、审核和网络的端到端时延承诺。

浏览器麦克风通过 AudioWorklet 产出24kHz单声道PCM16小包，经同源 WebSocket 到受控服务端，再连接固定官方地址。没有先录完整文件再上传的中间步骤。短录音转写仍作为另一种入口存在。

- **GPT-Live 1**：独立 Live 会话，支持同声输入输出与客户端委派。它自身不直接接收图片；共享画面进入受权限控制的后端 Responses 智能体。后端结果再作为有长度限制的委派返回进入通话。
- **Realtime 系列**：使用独立 Realtime 会话、服务端VAD、逐回应收据与函数调用。当前共享图像可进入会话，具体是否开放仍由能力与用户授权决定。应用一次只保持一个在途回应和一个后续待回应标记，防止无限创建收费响应。
- 浏览器可以静音、停止播报、结束、发文字补充和主动更新当前图；不能直接发送供应商 `session.update`、任意工具、URL或密钥。
- 单人通话可独立开关字幕。Realtime 检测到用户开口时按 Web Audio 时钟回报当前播放片段和实际播到的毫秒数。用户明确允许公开搜索后，每通可提交 1–3 条不同查询，具体上限取决于委派配置。结果保留来源。
- 实时字幕以项目 ID 累积，最终识别替换同一条暂态内容。Live 的后端委派将最新发言和有限的前文分别传入编辑智能体，并校验真实画布尺寸、保存版本和未保存参数。关闭共享或更换底图时作废原画面，Realtime 删除旧视觉项目，Live 收到新的上下文状态。版本、共享和权限发生变化时，迟到候选不能应用在现有画布。
- 连接票据绑定已登录账号、精确 Origin、准备会话和一次连接；60秒过期，票据不放URL。畸形握手在消费票据之前拒绝，异常握手有关闭监听与时限。
- 每5秒复核权限/会话/模型，心跳丢失、撤权、预算耗尽和停服会结束连接。应用单实例最多32个准备中的升级/活动连接，输入输出有字节预算和背压。
- Live 最终 `usage.seconds` 与 Realtime 逐 `response.done.usage` 分开记录。普通 WebSocket 1000关闭不是供应商费用收据；有输入但缺少回应收据、待返回调用或异常断线保留 unknown。
- 会话计费目前是运营定义的**有时限服务点单位**，包含有界委派成本；不是按供应商每秒/token自动扣款。实际供应商收据单独保存以供核验和未来分项定价。

已审查的精确 ID、音色和首方文档在 `models.ts`。运营只能启用具备真实协议档案的语音模型。产品公开存在、账户获准、所在地区可用及本项目付费实测是不同结论。

团队语音按同一作品分房间。成员音频分别转发和播放，支持同时说话。成员的短缓冲和 AI 的长播报缓冲彼此独立。加入 AI 后，只有主动授权当前邀请的麦克风进入实时混音。单声道 AI 输入中有重叠发言时，字幕统一标为“成员”。仅成员通话可在支持的浏览器中启用本机字幕语言包。AI 邀请复用服务端语音额度与委派，主持人离开会结束 AI，会话内其他人可继续通话。具体权限、容量和流协议见 [API 契约](../../apps/api/API_V4.md#631-team-voice-on-a-shared-artwork)。

## 4. 资源与记忆

个人/团队资源检索始终按当前 membership 与允许空间过滤。搜索返回的素材不是自动发送图片的授权；只有明确选中的图片才按配置进入视觉请求。长期标注属于当前用户，采用显式“记住”与可删除说明，不默认记人脸身份，不将私有标注共享给其他成员。离开团队以后，标注本身不能让用户继续读取原素材。

对话按稳定根 ID 分离，可新建和切换。入口列出100个会话根及每个会话最近30轮，模型父链上限256轮。o200k 文本估算与视觉、工具、输出预留共同控制预算。用户原话逐字保留，旧助手说明可压缩为原文入口，候选 ID、决策和版本仍在上下文。确认的约束与更正逐字保留，偏好和工作流按中英文词面相关性排序。上下文依据列出所用记忆和素材标注的版本。派发、结果发布时复核记忆版本、有效期、素材授权及会话。原文归档方式参考 [DeepAgents.js](https://github.com/langchain-ai/deepagentsjs/blob/main/libs/deepagents/src/middleware/summarization.ts)，按请求选取作用域记忆的机制参考 [Mem0](https://docs.mem0.ai/core-concepts/how-it-works)。

显式记忆支持个人、团队、项目、作品范围，带分类、来源轮次、有效期、乐观锁版本、删除与分页历史。模型只能提出包含用户原话证据的记忆草案，用户审阅并保存后才生效；不从照片猜身份。工作卡片仅支持五类白名单结构：澄清、候选、参数对照、参考与预算，所有动作引用已存在候选和应用动作，不执行模型 HTML、脚本或任意 URL。

Responses 文本增量经累积审核写入持久序号事件，完成时校验终包。工具、检索结果、上下文清单和停止状态一并记录。SSE 按最后序号恢复，每连接25秒轮转，单用户最多3个、进程最多128个。事件批次读取时复核会话与素材范围。文本运行可主动停止。派发前停止释放预占，已有有效回执时结算，结果不明时留待核验。原音频与实时画面 base64 不进入长期日志。分类型流事件参考 [Vercel AI SDK Stream Protocols](https://ai-sdk.dev/docs/ai-sdk-ui/stream-protocol)。

公开检索使用用户单独填写的查询词，单独派发一轮，私有编辑请求只接收经校验的公开证据。图片检索需要独立能力开关。云端图可在当前工作台查看缩略图并显式选为参考，公开图提供原图和来源页链接。供应商请求字段见 [OpenAI Web Search](https://developers.openai.com/api/docs/guides/tools-web-search)。

## 5. 失败与恢复不变量

- 发出前失败与可能已收费的失败必须分开。已派发但不明确的请求保持 hold，不自动退款/重试。
- 重放同一幂等请求先检查现有记录，不因画面后来变化而再创建一次付费请求。
- 老数据库恢复缺少独立日志中的派发事实时，全局停止新付费请求。普通 unknown 核验入口不能代替这类离线恢复；先按部署手册核对数据库与日志来源。
- 工作器退出必须等待已经发出的有界 HTTP 回执完成；结束通话后不再发布迟到候选。若结算响应本身不明，显示 unknown，不显示“已免费取消”。
- 生产依赖文件系统独占硬链接及目录 fsync，本轮验证为 Linux。没有宣称任意网络文件系统或 Windows 服务端具有相同的持久保障。

## 6. 验证与扩展顺序

本包单测验证真实编辑配方/渲染变化、有界工具调用、来源、审核、音色隔离与PCM跨包一致性。API测试使用真实原生PostgreSQL与真实本机WebSocket/TCP；外部服务是明确注入的协议fixture，未冒充真实OpenAI收费调用。浏览器音频硬件与用户账户需在目标HTTPS部署单独验收。

新增工具应按“共享DTO → 纯编译器 → 权限范围 → 人机确认 → 租约/版本 → 账本/发送证据 → 回归”顺序实现。新增模型同时补能力档案与负例，不能让前端选择未经映射的参数。新增持久上下文必须先定义删除、空间边界、预算和导出语义，不能仅把所有历史塞进提示词。
