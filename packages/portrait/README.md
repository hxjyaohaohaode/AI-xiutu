# 人像语义适配层

`@ai-xiutu/portrait` 把人物分析和用户参数编译为 `@ai-xiutu/editor` 的普通 V3 区域、绘制图层和液化笔触。它没有自己的隐藏渲染器，也不会修改原图。保存后的效果不依赖重新运行模型：预览、导出、版本重放继续使用同一份 RecipeV3。

这是**关键点与区域驱动的确定性美颜基线**。46 个注册控制均有实际像素或位移计算；分析模型、皮肤分割精度和最终妆容质量必须另外在真实照片上验收。测试中的合成关键点不代表人脸识别质量，不宣称达到商业修图软件的自动祛痘、发丝重建、三维重塑或逐帧美颜水平。

## 边界和数据流

| 层                | 输入与职责                                                 | 输出                           |
| ----------------- | ---------------------------------------------------------- | ------------------------------ |
| 分析运行时        | 规范方向的源图预览；加载已核验的模型；实际推理与取消       | 原图坐标关键点、轮廓、可选分割 |
| `AnalysisAdapter` | 校验配置、帧哈希、预览比例、算法版本、取消状态和有界纯数据 | `PortraitAnalysis`             |
| 语义编译          | 选择人物；校验每项参数及所需关键点；由真实位置生成操作     | `RecipeV3`                     |
| 图像内核          | 局部颜色、蒙版、混合、位移场、几何和导出                   | RGBA8 像素                     |
| 工作台            | 展示可用性、允许校正、明确提交、撤销、保存和版本冲突处理   | 用户确认后的修订               |

本包不做网络、账号、收费、模型下载，也不识别人物身份或对容貌评分。实际浏览器模型驱动在 `apps/web/src/editor/portrait.worker.ts`，其资源由部署配置和准备脚本管理。未配置模型时，不用固定关键点冒充推理结果。

## 原图坐标与分析契约

`PortraitAnalysis` 含 `schemaVersion:1`、`provider`、`algorithmVersion`、`frame`、`targets`、`segmentation` 和 `warnings`。`frame` 使用公共 `SourceFrame` 契约：

- `coordinates: 'source-normalized'`、`orientation: 'normalized'`；方向归一化后再计算坐标。
- `width`、`height` 是完整源图尺寸，不是缩略图尺寸。
- `contentHash` 是完整规范化源图的摘要。换图、重新解码改变像素或改变方向后，旧分析不得继续应用。
- 预览必须和原图保持比例。适配器允许缩放取整造成的至多一个原图长边单位的叉积误差；不接受裁过一部分却标注为整图的预览。

`validatePortraitAnalysis(input, expectedFrame)` 会复制并校验数据，拒绝未知字段、访问器、循环结构、非有限数、异常原型、稀疏数组、越界坐标和重复目标。调用方必须提供**当前**源图的 `expectedFrame` 验证关联；单独的 Recipe 不保存图像摘要，语义编译器不能凭 Recipe 判断当前画布是哪张图片。

目标 ID 为 `face-{哈希前12位}-{1…8}` 或 `body-{哈希前12位}-{1…8}`。当前数据模型最多 8 张脸和 8 个身体。它们是本次分析中的几何目标，不是跨照片身份，也不是永久跟踪 ID；重新分析后不能凭编号推断同一个人。

`face` 支持 468…512 个有界关键点，`body` 支持 33…512 个；这为同族模型的附加点留出空间。**当前语义规划使用 MediaPipe face/pose 的标准索引与轮廓语义。**替换供应商时必须映射到这一拓扑，或者新增独立语义编译版本，不能只把另一种任意点序列放进数组。

面部必须具备 `oval`、`leftEye`、`rightEye`、`leftBrow`、`rightBrow`、`lips` 的闭合轮廓；`innerLips` 用来排除口腔。`contourLoops` 只接受真正闭合的连接环。眉毛常由多段开放连接组成，适配器用 `contourHull` 取得全部连接点的凸包，不能把第一段开放眉毛曲线当成完整区域。关键点外推允许有限的图外坐标，但渲染轮廓必须裁到原图范围。

面部关键点坐标限制为 `[-1,2]`，身体关键点为 `[-8,8]`。身体范围较宽是因为真实 Pose 模型会对上半身照片中的不可见膝踝输出远在图外的估计值；保留有界的原始估计，可以避免因此丢弃同图有效的人脸与肩颈。**这些图外点不会启用身体功能**：每项工具仍要求它实际需要的全部关节位于 `[0,1]` 且 visibility 至少 0.5，不会钳位点位后冒充可见肢体。

分析可以附带皮肤、头发和背景三个 V3 蒙版。皮肤操作把人物轮廓与皮肤分割相交，并扣除眼睛、眉毛和嘴唇；没有分割时明确退化为轮廓区域，不能称为精确皮肤材质检测。头发和背景蒙版是后续选择、保护或编辑的输入，不会自动生成头发或自动开启背景保护。

## 公共接口

```ts
const adapter = createPortraitAnalysisAdapter(driver);
const analysis = await adapter.analyze(
  {
    image: preview,
    contentHash: currentFrame.contentHash,
    includeBody: true,
    includeSegmentation: true,
  },
  { frame: currentFrame, signal },
);

const availability = portraitToolAvailability(analysis, targetId);
const previous = portraitValues(recipe, targetId);
const colors = portraitMakeupColors(recipe, targetId);
const next = applyPortraitValues(
  recipe,
  analysis,
  targetId,
  { ...previous, lipstick: 45 },
  undefined,
  { makeupColors: { lipstick: [174, 38, 64, 210] } },
);
```

| API                                                                                 | 行为                                                                                         |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `createPortraitAnalysisAdapter(driver)`                                             | 实现公共 `AnalysisAdapter`；驱动负责实际推理。调用前后检查取消；拒绝错误的算法版本和源图绑定 |
| `validatePortraitAnalysis(input, expectedFrame?)`                                   | 返回独立的有界纯数据副本；有当前帧时做完整绑定检查                                           |
| `portraitToolAvailability(analysis, targetId)`                                      | 返回当前目标各工具 `{id, available, reason}`；身体按每项实际需要的关节判定                   |
| `applyPortraitValues(recipe, analysis, targetId, values, fallbackColor?, options?)` | 用完整人物参数快照替换该目标的既有操作；没有传入的参数回到零；返回新配方，不改调用方对象     |
| `portraitValues(recipe, targetId)`                                                  | 还原已保存、已注册、在范围内的人物数值；不把 RGBA 追溯数据当成美颜参数                       |
| `portraitMakeupColors(recipe, targetId)`                                            | 还原每个妆容工具独立的 RGBA8 颜色                                                            |
| `detachPortraitTarget(recipe, targetId)`                                            | 把该人物的全部自动操作转成独立精修操作；更换唯一 ID、保留追溯与像素，并退出自动滑条归属      |

`applyPortraitValues` 的第六参数只覆盖所列妆容颜色。调整口红时传 `makeupColors.lipstick`，不会使眉妆、腮红一起变色。旧第五参数保留为**新妆容**的回退颜色，已有工具优先使用保存颜色。零强度会移除该工具的效果；完全零值会移除该人物语义操作，即使重新分析的轮廓不完整也能复原。

原始图像像素不在 `PortraitAnalysis` 中；模型分析与公开保存数据不应携带任意 URL、脚本或供应商密钥。实际驱动必须响应 `AbortSignal` 或被 Worker 终止；包装层在推理后拒绝迟到结果，但不能把同步第三方模型计算变成可中断计算。

## 已实现控制和数学含义

所有控制中性值是 0、步长建议 0.1。参数范围为 `[-100,100]`，以下标注“单向”的工具为 `[0,100]`。范围用于用户参数，不等同角度、毫米或肤色等级。没有统一的“最佳美颜数值”，没有强制自动美化。

| 分组 | 控制                                     | 当前实现                                                          |
| ---- | ---------------------------------------- | ----------------------------------------------------------------- |
| 美肤 | 磨皮（单向）                             | 面部皮肤蒙版内保边柔化，最高映射到柔化 75                         |
| 美肤 | 纹理弱化（单向）、皮肤肌理               | 局部高频对比弱化/增强；两项合成为同一有界纹理参数，不识别单条皱纹 |
| 美肤 | 肤色明暗、肤色冷暖、气色                 | 局部曝光 ±0.7、色温 ±35、色偏 ±14 与自然饱和度 ±12                |
| 美肤 | 匀肤（单向）                             | 色度降噪与局部清晰度降低；没有重新合成皮肤纹理                    |
| 美肤 | 眼下明暗、亮眼、眉毛增强、鼻梁光影       | 独立区域曝光或细节；眼下暗部不自动被判定成黑眼圈                  |
| 面部 | 瘦/宽脸、窄/宽脸、下脸收窄、颧骨、下颌角 | 基于面轴与轮廓的双侧有界推移，负值反向                            |
| 面部 | 小/大脸、太阳穴                          | 在相应位置施加收缩/膨胀位移场                                     |
| 面部 | 下巴长短、额头比例                       | 沿面部方向推移；不是生成发际线                                    |
| 面部 | 眼睛大小、眼间距、眼睛旋转               | 双眼分别缩放、相反方向推移和局部旋转                              |
| 面部 | 鼻翼宽度、鼻尖位置、鼻长                 | 鼻部各自锚点与半径的双向局部推移                                  |
| 面部 | 嘴唇大小、嘴角、眉毛粗细                 | 嘴唇缩放、实际嘴角位置推移、眉上/下边缘相反方向推移               |
| 身形 | 头部大小、颈部比例、颈部宽度、肩宽       | 耳、肩关键点决定头颈/肩位置与方向                                 |
| 身形 | 手臂、腰、胯、大腿/小腿轮廓              | 可见关节之间的分段径向收缩/膨胀                                   |
| 身形 | 腿部比例、身形纵向                       | 沿肩—髋方向对髋、膝、踝分段推移；有明确的纹理拉伸限制             |
| 美妆 | 口红、眼影、腮红（单向）                 | 关键点蒙版内的 `color` 混合，口红排除口腔                         |
| 美妆 | 修容、高光妆、卧蚕妆（单向）             | 相应位置的柔边 `soft-light` 混合                                  |
| 美妆 | 眉妆（单向）                             | 眉毛蒙版内的 `multiply` 混合                                      |

美妆颜色为连续 RGBA8，不限于默认色卡；工具强度、色彩 alpha、图层 opacity 和蒙版权重共同决定实际覆盖。蒙版之外保持原像素。手动妆容、克隆祛瑕、涂鸦、橡皮和像素笔属于编辑器绘制图层能力，可以与这些操作共存。

面部方向在**原图像素空间**由两眼轴和嘴部方向确定，再映射回归一化坐标，避免非方形图片和侧转/倒置照片使推移方向偏斜。轮廓位置是模型估计，局部液化不是三维重建，较大参数仍可能拉伸背景或邻近纹理。需要背景保护时使用 V3 的显式保护蒙版，并在最终图上检查。

身体每个工具检查自己的必需关节，visibility 至少 0.5 且位于原图内。只看得到肩膀时仍可调肩宽，看不到膝踝时不能伪造腿部调整。具体索引和范围在 `catalog.ts` / `plans.ts`，UI 应使用可用性接口而不是自己复制一套条件。

## 可替换、可重放的操作归属

所有生成的区域、图层、笔触带 `origin`：

```ts
{ moduleId: 'portrait.basic.v1', instanceId: targetId,
  parameterId: 'lipstick', value: 45,
  parameters: { lipstick: 45, makeupR: 174, makeupG: 38,
                makeupB: 64, makeupA: 210 } }
```

图像内核不执行 `origin`，它只是严格受限的追溯数据。规划器仅替换 `moduleId + instanceId` 同时匹配的操作，保留手动图层、别的人物、区域组和其他插件操作。重复拖动同一滑条不会不断叠加新效果。多项皮肤控制合并为一个皮肤区域，其他局部按需要生成。

自动操作还保存整个人物 primitive 集合的有界完整性校验值。再次调自动滑条前，编译器核对内容、数量与内部顺序；检测到手动修改、部分删除、重新排序或旧操作缺少标记时，拒绝重建并保留现有配方，要求先转成独立精修。该校验是防止误覆盖的确定性校验和，不是密码学签名，也不承担权限校验。未变更的自动操作更新时保留相对手动层的位置，新出现的操作才追加到末尾。

需要手动修改自动生成的蒙版、笔触或参数时，先由用户明确调用 `detachPortraitTarget`，一次性将该人物全部自动操作转成 `portrait.manual.v1`。整个人物一起转换，是因为皮肤控制合并在同一区域且追溯保存完整参数快照；逐项转换会造成残留滑条值与实际归属不一致。转换不会改变像素，也不会丢失原始追溯。操作 ID 同时重命名为不重复的 `manual-*`，因此 UI 应清空旧的区域/图层选择。之后自动滑条回到零；再次调节会在独立精修结果上新增自动效果，工作台必须明确说明，不能让用户误以为仍在更新原来的精修层。

新算法必须改变模块版本或明确迁移语义；不能偷偷修改已保存的 primitive 再声称旧版本仍可重复。当前人物语义配置从 primitive 的 `origin.parameters` 恢复；操作来源丢失后仍能渲染像素，但不能保证还原原来的语义滑条。

## 数量、性能与验收边界

- 分析预览至多 4,194,304 像素；分析帧尺寸上限 67,108,864 像素只是数据契约上限，**不代表 V3 允许渲染 64MP**。
- V3 当前源图/输出上限各为 16,777,216 像素；默认执行预算为 4,194,304 像素。调用方提高预算前需做真实设备验收。
- 全配方共有 12 个新区域、6 个区域组、24 个绘制图层、64 个液化笔触和 128 个蒙版节点预算，和手动编辑共享，不能按人物数分别放大。
- 一个全部打开的面部配置占 5 个区域、7 个绘制图层、32 个液化笔触；测试确认两个全配置面部占 10/14/64。此时不能再添加新的液化操作，须减少控制、分支或明确栅格化后再编辑。
- 8 张脸可以被识别和选择，不等于 8 张脸能同时无限开启所有效果。UI 应显示剩余额度式的操作预算并保留用户原配方，不在超限时静默截断。
- 当前美妆和人像几何仍为二维近似；遮挡、极端侧脸、眼镜、复杂发型、小脸、强光和多人重叠需要真实图片验收。没有自动补全缺失五官。

执行 `npm run typecheck -w @ai-xiutu/portrait` 和 `npm test -w @ai-xiutu/portrait` 验证本包契约。测试覆盖真实渲染、人物独立性、原图绑定、目标预算、取消、轴线与混合。真实模型下载、浏览器推理、实际照片质量和设备速度属于工作台集成测试，不能用这些单元测试替代。

## 参考与后续扩展

Google 官方文档说明 [Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker?tab=Web)、[Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker?tab=Web) 和 [Image Segmenter](https://developers.google.com/edge/mediapipe/solutions/vision/image_segmenter) 的输入、输出和推理接口。本包从这些公开的几何/分割结果生成自主实现的编辑操作，不包含商业修图软件的专有算法。

下一步应分别接入和验收：高质量皮肤材质分割、缺陷/皱纹专门检测与修复、遮挡感知的人像形变网格、头发/眉毛重建、可交互精细关键点校正、多人跨帧追踪。各模块保持 `AnalysisAdapter → 可校验分析数据 → 明确版本的 Recipe primitive`，并为其真实能力增加独立质量数据，不能只增加菜单名。
