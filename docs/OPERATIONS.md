# 部署、外部配置、成本与网络

本文与 `DESIGN.md` 配套：设计文档解释项目怎么工作，本文说明怎样运行、需要哪些真实账户，以及哪些验收还不能被代码测试替代。

V4 新增的协作、智能体/连续语音、保留原件、迁移 8～10、发送日志恢复与代理配置，见 [OPERATIONS-V4.md](OPERATIONS-V4.md)。本文保留基础部署及旧 AI 任务说明；涉及旧阶段测试环境的陈述已标明时间归属，不代表本轮能力上限。

## 1. 当前部署选择

基线采用同源网页/API + PostgreSQL + 私有文件卷 + 独立 AI Worker。没有强制 Redis、商业鉴权服务、海外 CDN、外链字体或常驻 GPU。图片基础编辑在浏览器完成；旧 AI 任务由 Worker 调用已配置供应商。V4 的有界智能体、语音桥接和原件任务由 API 接线，实际媒体解码在受限子进程执行；单机与扩容限制见 V4 手册。

开发可以完全本地进行；生产不应把“免费额度”当作不限量、持久化和稳定性的保证。旧基线曾以 **2 vCPU、4 GiB 内存、足够容纳素材与备份的磁盘**作为小规模试运行的起点评估建议，并没有形成已测容量保证。V4 可选媒体覆盖的 4g 限制用于 API 与子进程容器整体，PostgreSQL 和其他服务仍需额外宿主机内存；不能把旧建议直接当作开启 200MP/RAW/HDR 后的整机需求。具体预算见 V4 手册。

费用需要拆成四项：服务器/带宽、存储与备份、短信/审核、AI。基础软件架构不要求按用户数购买托管席位，但供应商调用并不免费。仓库未执行任何购买、订阅变更或收费模型调用。

## 2. 本地开发

### 2.1 安装与配置

```sh
npm ci
npm run vision:prepare
cp .env.example .env
```

在私有 `.env` 中设置随机 `SESSION_SECRET`（至少32字符），保持 `APP_ORIGIN` 与实际网页 origin 完全一致。不要把密钥写在前端变量、源码、聊天截图或 Git 中。`.env.example` 所有密钥均为空；它不是可直接访问第三方账户的配置。

### 人物模型的同源资源

`vision:prepare` 从 Google 官方版本 1 地址下载 face_landmarker、pose_landmarker_lite、selfie_multiclass_256x256 三个模型（合计约 25.91 MB），逐一验证源码中固定的 SHA-256，再复制 npm lock 锁定的 MediaPipe 1.2.2 WASM 加载器和二进制。资源在 `apps/web/public/vision`，不放进 Git；浏览器运行时全部从本网站加载，照片不因人物识别自动上传。

Docker 构建默认准备这些资源；明确不部署时可设置构建参数 `WITH_PORTRAIT_MODELS=false`，相应自动功能会报告未安装。离线构建需先建立可信的已校验构建缓存，不能把任意同名模型当作正确资源。模型下载失败使启用模型的构建失败；没有静默假成功。

自动分析需要 OffscreenCanvas 和可用 WebGL 2。当前 MediaPipe JS 输入路径即使 CPU delegate 也会使用 WebGL；CPU 推理不代表不需要图形上下文。分析进程有 60 秒截止、显式取消和换图后结果丢弃。V3 阶段测试云浏览器不能正常完成该图形输入路径，因此当时只验证了明确不可用的分支；不能将模型成功下载当作识别成功。V4 的像素重放与原生 CPU 分析证据也不替代目标设备上的浏览器推理验收，详见 [V4 图像核查](verification/v4-image-review.md)。手工局部、绘制、液化和严格同图标注导入可独立运行。

Caddy 对 `/vision/*` 不采用 SPA 回退，缺失文件返回 404；CSP 仅增加执行 WASM 所需的 `wasm-unsafe-eval`，不加入普通 `unsafe-eval`。开发服务器对白名单固定 WASM JS 加载器提供透传，解决 Vite 动态导入 public 文件的限制，不暴露任意文件路径。

模型与 SDK 的来源、许可证及质量边界见 [人物资源说明](VISION.md)。MediaPipe 的 Apache-2.0 资源不意味着测试照片也拥有相同授权。

### 2.2 不依赖系统数据库的开发

```sh
npm run dev:lite
```

数据保存在 `.data/pglite-dev`。该工具使用 PostgreSQL 18 WASM/PGlite，通过 PostgreSQL 协议供现有 `pg` 查询；它不是 JSON 模拟数据库。但只有一个数据库执行后端，不能用它证明原生 PostgreSQL 的真实多连接竞争、故障恢复和生产性能。

开发库不能被两个独立 PGlite 进程同时打开。要创建初次运营账号或运行 `doctor:lite`，先停止 `dev:lite`。运营初始化所需的三个变量见环境模板；执行 `npm run admin:lite` 后移除临时密码变量，再重启开发服务。没有默认账号或固定密码。

### 2.3 原生 PostgreSQL

设置独立 `DATABASE_URL`、`TEST_DATABASE_URL`，然后：

```sh
npm run db:migrate
npm run admin:create
npm run dev
```

`npm run db:local` 是普通非 root 用户可选的原生开发 PostgreSQL 启动器。旧阶段记录的“工作环境不能启动原生服务”只属于当时的执行条件；2026-11-10 的 V4 后端已使用独立临时 PostgreSQL 18.6 与多连接池执行真实 SQL 集成，见 [后端审查记录](verification/v4-backend-review.md)。这不等于 `db:local` 脚本在每个平台都已验收。该命令仅在 `.env` 不存在时生成本地连接和随机密钥配置；已有 `.env` 时保留原文件，需要根据私有 `.data/local-postgres.json` 手动更新连接（端口55432）与密钥。模板占位地址不会自动被覆盖；使用系统 PostgreSQL 或 Compose 也可。

## 3. 真正启用账号与 AI

### 手机验证

配置腾讯云的真实 Secret ID/Key、SMS App ID、已审核签名与注册/登录/重置三种模板。模板参数必须与 `TENCENT_SMS_CODE_ONLY` 配置匹配。供应商接受发送和手机实际收到是两件事，需要用拥有者授权的真实手机号单独验收。

注册包含手机号验证码、密码与可选邀请码；验证码不能由运营面板查看。运营预先添加的账号保持待验证状态，既不赋予默认密码，也不直接视为已验证。命令行初始运营账号是部署持有者的受控配置，审计会记录这一来源。

### 四类 AI 任务

| 能力     | 服务器关键配置                                                                        | 运营目录                               | 外部依赖                   |
| -------- | ------------------------------------------------------------------------------------- | -------------------------------------- | -------------------------- |
| 调整建议 | `AI_PLAN_ENABLED=true`、`DASHSCOPE_API_KEY`、`QWEN_BASE_URL`                          | provider=qwen，operation=edit-plan     | Qwen 文本、腾讯文本审核    |
| 文案生成 | `AI_TEXT_ENABLED=true`、同上                                                          | provider=qwen，operation=generate-text | Qwen 文本、腾讯文本审核    |
| 图片生成 | `AI_IMAGE_ENABLED=true`、`ARK_API_KEY`、`ARK_IMAGE_MODELS_JSON`                       | provider=ark，operation=generate-image | Ark 生图、文本及图像审核   |
| 语音识别 | `AI_SPEECH_ENABLED=true`、`DASHSCOPE_API_KEY`、`QWEN_ASR_BASE_URL`、`QWEN_ASR_MODELS` | provider=qwen，operation=transcribe    | Qwen ASR、转录后的文本审核 |

文本与图像审核分别设置 `TENCENT_MODERATION_BIZ_TYPE`、`TENCENT_IMAGE_MODERATION_BIZ_TYPE`，共用受控腾讯凭据和地区。不能把“模型自己会审核”当作已接通平台的内容审核。

`ARK_IMAGE_MODELS_JSON` 是实际模型/推理接入点 ID 到已审查能力档案的绑定，最多16项。例子只是结构，不提供有效模型 ID：

```json
[{ "id": "your-enabled-model-id", "profile": "seedream-5-flash" }]
```

档案约束取自官方接口，服务端还取运营范围与 `AI_IMAGE_MAX_PIXELS` 的交集。默认平台预算为16,777,216像素；不支持该分辨率的模型仍不能选择。5-pro/flash、5-lite、4.5、4.0 的能力不是互换的。更换供应商能力必须更新档案和契约测试，不依赖名称猜测。

本版本 Ark 输出请求使用一张 Base64 图像，保留上游 AI 水印；不会跟随上游任意 URL，也不会假装多图或确定性遮罩编辑已支持。输入参考图是构图/内容参考，不能保证像素级保留。

图片生成的压缩返回字节上限7,000,000，规范化后用于审核的文件也受该调用预算限制。高像素、高噪声图可能超出这一边界；任务会停在待核验状态，不能发布未审核图片。要服务更大图像，应增加经过验收的私有对象存储审核通道和资源预算，不能擅自缩图审核、再发布未审核的原字节。

所有开关默认关闭，已配置目录不代表运行时供应商已启用。`npm run doctor` 检查本地配置、数据库迁移、目录和能力描述；V4 还检查助手日志一致性、原生媒体 import 与代理配置形状。它不发送短信、审核或模型请求，也不测试目标网络，不能证明真实账户已获准调用。

模型目录检查采用只读一致快照，每页200条遍历全部配置，仅展示40条精简样本和`modelCount/modelsOmitted/invalidModelCount`。助手配置即使位于未展示页，校验失败仍使诊断退出失败；样本截断不是跳过检查。完整模型参数仍由运营目录接口提供。

### OpenAI Images 的独立开关

使用 OpenAI 时，除 `AI_IMAGE_ENABLED` 外，还需要 `OPENAI_IMAGE_ENABLED=true`、服务端 `OPENAI_API_KEY`、非空的 `OPENAI_IMAGE_MODELS` 精确白名单、已启用运营目录和真实文字/图片审核配置。个人 ChatGPT 订阅不是 API 凭据。请求固定到官方 `api.openai.com`，浏览器不能选择代理地址、上传供应商密钥或把任意 URL 交给 Worker。

默认整批最多 4 张、总像素 16,777,216、原始/规范化输出分别不超过 28,000,000 字节；运营的单次上限可进一步收紧。按质量设置单张整数服务点，整批报价乘输出数量并冻结。运营定价要覆盖输入参考图、允许的最大尺寸、文本/图片审核以及 unknown 核验损耗，不能把同一个服务点写成所有模型统一的美元价格。完整配置、8 个精确模型和官方参数来源见 [OpenAI 接入契约](../packages/multimodal/OPENAI.md)。

当前 SVG/GIF、流式部分图像和自动尺寸没有放开，原因与接口状态明确返回。配置成功不表示已完成真实 OpenAI 账户/地区/账单验收。

## 4. 生产容器与持久化

仓库提供 `compose.yaml`：db、一次迁移、api、worker、web。API 和数据库不公开宿主机端口，Caddy 提供同源入口。数据库、素材、AI 发送日志和 HTTPS 状态有独立卷；API 与 Worker 共享素材和发送日志。

V4 可通过 `compose.media.yaml` 切换可选 `server-media` 镜像，显式启用原件导入与 RAW/HDR 原生依赖。它增加容器总内存/CPU/PID 与 capability 限制；实际命令、单进程限制和新 CI 尚未执行的状态见 [V4 部署手册](OPERATIONS-V4.md)。

生产至少配置：

- 随机 URL-safe `POSTGRES_PASSWORD`，建议使用随机十六进制值；Compose 的数据库 URI 直接插值，含 `@/:?#` 等字符需要另外正确编码。
- 随机 `SESSION_SECRET`。
- `APP_DOMAIN` 为实际域名，`APP_ORIGIN=https://实际域名`，安全 Cookie。
- 外部服务密钥及开关，或者明确保持关闭。

```sh
docker compose build
docker compose up -d
# 首次运营账号通过安全的临时环境变量传入 bootstrap，完成后移除。
docker compose run --rm api npm run admin:create
```

使用 `:80` 可进行本地 HTTP 调试；真实远程录音需要受支持浏览器、HTTPS 和用户麦克风授权。Caddy 允许本源麦克风，不开放摄像头和定位，CSP 仅允许本源脚本、图片/Worker所需blob、音频试听blob。不能把开发服务器的录音成功直接当作生产反向代理也正确。

`TRUST_PROXY_HOPS=1` 只适用于当前 API 仅能从单层受控 Caddy 到达的拓扑；直接暴露 API 时使用0。不要为了获取真实IP而信任任意 X-Forwarded-For。

镜像基础标签需要在实际发布环境验证后固定到镜像摘要。容器构建、迁移、健康检查和恢复的实际结果记录在验证文档；配置文件存在不等于容器已启动成功。

## 5. 网络与现有 JMS 代理

用户拥有的订阅信息只有服务网站，没有节点地址、协议、账号配置、流量限额和服务条款。因此本次**没有真实测试该订阅**，也没有把首页能打开称为代理已可用。

需要分别验证两条链路：大陆用户浏览器到网站，以及网站服务器到供应商。服务器出口代理只能影响第二条，不能直接修复第一条的 DNS、机房线路、TLS、图片下载和移动运营商质量。

国内模型适配器与短信/审核可按实际账户使用相应官方地区端点；V4 的 OpenAI 图像、助手及语音则有自己的固定官方端点与地区/账户要求，不能将所有调用概括为国内链路。应用静态资源同源提供，没有要求用户自行开启代理，也没有把个人订阅节点作为生产必需环节。浏览器系统朗读的语音可用性由系统和浏览器决定。

个人代理如果允许相应用途，可以作为受控开发诊断的一种出口；仍要单独核实支持的协议、并发、稳定性、出口地区、隐私处理和供应商地区规则。不能仅凭“代理能连通”就声称账户、付费服务和面向大陆用户的生产可用性已成立。当前真实适配器端点有白名单，不提供向任意节点或中转站上传用户照片的前端配置。

V4 的 Node fetch 出口采用启动环境 `NODE_USE_ENV_PROXY=1` 及 HTTP(S) 代理变量；`ASSISTANT_EGRESS_PROXY` 仅配置连续语音上游 WebSocket，两者不互相替代。SOCKS/SS 订阅需另外配置受控 HTTP CONNECT 桥，项目不自动解析订阅或安排节点。具体启动方式、`NO_PROXY` 和未实测边界见 [V4 网络章节](OPERATIONS-V4.md#8-服务器出口代理与大陆访问)。

正式稳定性验收至少覆盖三家大陆运营商、Wi-Fi/移动网络、手机/平板/电脑、弱网重连、较大素材上传、异步任务轮询、审核延迟、模型超时和额度核验。记录成功率与 p50/p95 时延，同时区分网站响应、排队时间、供应商耗时和下载。没有这些样本，本项目不会承诺“大陆稳定访问已验证”。

## 6. 套餐与成本核算

运营可配置免费月度额度和套餐目录，按模型/任务设置整数服务点。服务点不是人民币，也不能把返回 token 数随意当成所有供应商统一的图片价格。

先在自己的供应商账单中记录每个 task/model/尺寸的实际成本，再制定点数价格：

`月成本 = 服务器与带宽 + 存储与备份 + 短信 + 输入/输出审核 + 文本/图片/ASR/智能体/语音调用 + 不确定结果核验损耗`

`每次服务点 ≈ 供应商实际成本 + 审核与基础设施摊销 + 运营预留`，换算比率由运营制定并记录版本。界面展示每次任务的点数，入队冻结当时价格，不能在已预占后偷偷改价。

免费额度按亚洲/上海自然月、用户唯一发放。团队使用独立钱包，创建多个团队不会复制免费权益。没有余额时明确拒绝，不把用户的个人点数自动借给团队。

本版本支持带理由、幂等键和审计的人工正负额度调整；套餐是目录配置，**在线支付未启用**。人工核对付款后赠额的商业流程需要明确订单/凭证/退款规则，不能把微信收款截图或打赏码识别结果当成系统自动验证的到账事实。后续接微信支付等正式商户接口时，要增加验签、幂等订单、交易/退款/对账后再启用支付入口。

仓库没有购买服务器、域名或免费套餐，也没有把未来促销价写成长期价格。实际采购时应以供应商当前控制台价格、地区、带宽、存储和账户条件计算，避免因初期免费而绑定不可迁移的数据路径。

## 7. 备份、恢复与敏感数据

需要一起管理数据库、私有素材、发送日志三类数据。V4 私有卷还包括 `media-v1/` 原件/母版/瓦片，派发卷包括 `assistant/` 下新日志。只备份数据库不能恢复图片；只恢复旧数据库而丢失最新发送事实可能造成重复收费。因此发送日志和数据库恢复要先核对，再开放 Worker、助手与语音入口。

建议演练流程：停止新接纳，给 API/Worker 已派发工作有界收尾时间，再停写；在隔离环境恢复数据库和相应素材；对比发送日志与派发摘要；把未确认任务保持 unknown；核验后逐步开放。V4 助手检测到日志/数据库不匹配时以 `ASSISTANT_RECOVERY_REQUIRED` 阻断付费；普通退点不修复这种恢复故障。不要为了恢复启动而直接删除日志。可执行备份示例与证据边界见 [V4 恢复章节](OPERATIONS-V4.md#3-数据库迁移备份与恢复)。

普通图片上传的规范化仍应用方向、转换到 sRGB PNG 并去除额外元数据；这条旧接口不保留原始容器。V4 新增明确选择的高级导入，逐字节保存原件，另生成母版、代理与瓦片，分别受 Asset ACL 和容量限制。旧素材不会凭迁移补回已丢失原件；高位深母版格式转换也不包含浏览器配方编辑，详见 [V4 媒体章节](OPERATIONS-V4.md#7-媒体原件母版代理图与实际预算)。

队列里的原音频在执行终态后被移除；未开始任务的音频、过期会话/验证码、限流桶、事件和孤立媒体需要按部署方要求配置周期维护。当前版本不宣称已实现完整数据保留/删除管理控制台。任何物理素材清理都要遵守跨项目副本引用，不能按单个资产删除即直接 unlink。

上传和 AI 图片的发布失败清理使用与原发布事务相同的 storage key 事务锁，先等原事务结束，再查询全部资产记录引用，包含已标记删除但仍保留的记录及完成复制的引用。只有权威确认未挂载时才删除；COMMIT 回包丢失、拿锁或查库失败时保留未确认的私有文件。不要将这些文件直接视作可删除垃圾，后续维护仍需按引用与保留规则核验。
