# V4 部署与运营手册

本文对应 V4 代码：数据库迁移 1～10、Recipe V4、同作品租约协作、资源记忆、用量看板、上下文智能体、连续语音与保留原件导入。基础账号、短信、旧 AI 任务和普通容器部署继续参照 [OPERATIONS.md](OPERATIONS.md)；产品数据链见 [DESIGN.md](DESIGN.md)，实际请求字段见 [API_V4.md](../apps/api/API_V4.md)。

**配置就绪、协议测试通过、生产账户可调用和目标网络可达是不同验收结果。** 本轮没有使用生产密钥完成收费模型调用，没有实测用户的 JMS 订阅，也没有完成中国大陆多运营商可用性验收。以下是按代码可执行的部署步骤与运营边界，不是已经上线的服务承诺。

## 1. 运行组成与启动

| 进程/存储      | V4 责任                                                   | 持久性与资源边界                                                         |
| -------------- | --------------------------------------------------------- | ------------------------------------------------------------------------ |
| 网页与 Caddy   | 同源静态资源、API 反向代理、语音 WebSocket                | 需要实际 HTTPS、正确 Origin 和浏览器麦克风权限                           |
| API            | 登录与 ACL、协作轮询/命令、智能体、语音桥接、原件导入任务 | 语音连接、待分享截图和部分并发计数在单进程内；不能直接承诺多实例无缝迁移 |
| 独立 AI Worker | 原有生图、文案、参数建议、短录音转写任务                  | PostgreSQL 队列与写前发送日志；不是新增语音连接的宿主                    |
| 媒体子进程     | 真实解码、母版/代理图/瓦片及格式转换                      | Linux `prlimit`，每 API 进程一个执行槽；不是无界计算池                   |
| PostgreSQL     | 版本、权限、租约、候选、派发、容量、服务点账本            | 生产使用原生 PostgreSQL；PGlite 仅作开发替代                             |
| 私有素材卷     | 普通素材、保留原件、母版、瓦片与未完成导入                | 同一部署的 API/Worker 必须看到一致存储；不能公开为静态目录               |
| 独立派发日志卷 | 原有任务日志与 `assistant/` 子目录                        | 文件及目录 fsync；应与数据库一起纳入备份/恢复核验                        |

### 1.1 本地开发与检查

仓库要求 Node 24。在仓库根目录安装锁定依赖，按环境模板填入自己的私有配置；不要覆盖已有 `.env`：

```sh
npm ci
cp .env.example .env
npm run vision:prepare
```

先设置真实 `DATABASE_URL`、独立测试库 `TEST_DATABASE_URL`、随机 `SESSION_SECRET` 和精确 `APP_ORIGIN`。默认关闭外部收费能力，然后：

```sh
npm run db:migrate
npm run doctor
# 首次部署才通过受控的 BOOTSTRAP_ADMIN_* 环境创建运营账号。
npm run admin:create
npm run dev
```

`dev` 在启动 API、Worker、Vite 前执行迁移；`npm start` 只启动 API，不替代部署迁移。生产非容器运行可分别使用 `npm start` 与 `npm run worker:ai`，网页使用 `npm run build` 的产物和受控反向代理。初始运营账号创建后移除临时密码配置。没有默认密码或假验证码。

没有系统 PostgreSQL 时可用 `npm run dev:lite`；开发库目录只能由一个 PGlite 执行进程打开。运行 `admin:lite` 或 `doctor:lite` 前先停止开发服务。PGlite 能执行真实 PostgreSQL SQL，但不证明原生多连接竞争。2026-11-10 的 V4 后端已在独立临时原生 PostgreSQL 18.6、多连接池和真实本地 TCP 下执行定向集成，证据见 [后端审查记录](verification/v4-backend-review.md)；这不等于部署者的生产数据库已经验收。

`doctor` 检查配置、实际迁移清单、私有目录写入/fsync、能力目录、助手日志与数据库一致性、媒体运行时 import 和代理配置形状。它不会发短信、请求审核、调用付费模型或验证网络连通。输出 `ready`/`nativeReady` 必须按这个范围解释。

### 1.2 容器启动

基础部署继续使用 `compose.yaml`：

```sh
docker compose config --quiet
docker compose build
docker compose up -d
docker compose exec -T api npm run doctor
```

需要可选 RAW/HDR 原生依赖时，使用已经提供的媒体覆盖文件：

```sh
docker compose -f compose.yaml -f compose.media.yaml config --quiet
docker compose -f compose.yaml -f compose.media.yaml build
docker compose -f compose.yaml -f compose.media.yaml up -d
docker compose -f compose.yaml -f compose.media.yaml exec -T api npm run doctor
```

`server` 已安装 `util-linux`，具备普通静态媒体处理所需的 `prlimit`；`server-media` 另外安装固定 Python 原生依赖，并设置 `/opt/media/bin/python`。覆盖文件只把 API 切换到该镜像并启用高级导入，旧 AI Worker 不因此变成媒体队列。

媒体覆盖默认把 **API 及其媒体子进程合计** 限制在容器 `4g`、2 CPU、192 个 PID，并设置 `cap_drop: ALL`、`no-new-privileges:true`。`MEDIA_CONTAINER_MEMORY` 和 `MEDIA_CONTAINER_CPUS` 是 Compose 插值项，可以调整容器预算；不是图像算法参数。PostgreSQL、Caddy、AI Worker 和宿主机仍需要额外内存。容器总内存限制与每个解码进程的 4GiB 地址空间上限是两个独立限制，后者不代表该进程可独占容器全部物理内存。

当前 Compose 没有提供完整的解码专属网络/文件系统沙箱。API 需要网络和私有数据访问；`prlimit`、去 capabilities 与非 root 运行不能自动隔离同容器内所有系统调用。进一步生产隔离应结合只读根目录、最小挂载、网络分区、磁盘配额与专用处理进程部署设计，不把已有配置描述为已经完成这些能力。

新增 CI 已配置 `server-media` 构建、在 memory/PID/capability 限制下执行真实 `nativeReady` 探测和媒体单测。**编写本手册时，这条新增 CI 路径尚未实际执行**；结果以对应提交的 CI 记录为准，不能用本地原生环境结果代替容器结果。

## 2. V4 新增配置与启用条件

全部配置在服务器端；不要使用 `VITE_*` 暴露供应商密钥或代理地址。已有短信/审核/图片配置仍有效，下面列出 V4 相关增量及共同依赖。

| 配置                                              | 默认/用途                                      | 启用边界                                                                                               |
| ------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `AI_ASSISTANT_ENABLED`                            | `false`；普通上下文智能体                      | 还须服务端 `OPENAI_API_KEY`、已配置文本和图片审核、启用的助手模型目录                                  |
| `AI_VOICE_ENABLED`                                | `false`；连续语音                              | 依赖助手整体就绪；还须受支持语音档案及启用的后端模型                                                   |
| `OPENAI_API_KEY`                                  | 空；真实 API 凭据                              | 图片和助手可以复用该服务器变量；个人 ChatGPT 订阅不等于 API 凭据                                       |
| `AI_JOURNAL_DIR`                                  | 模板为 `.data/ai-dispatch-journal`             | 新助手日志在其 `assistant/` 子目录；未配置时助手退回 `STORAGE_DIR/assistant`，生产应显式指定独立持久卷 |
| `ASSISTANT_EGRESS_PROXY`                          | 空；语音上游 WebSocket 的 HTTP CONNECT 出口    | 仅接受受控 `http:`/`https:` 代理；不配置 Responses/Images 的 fetch 出口                                |
| `NODE_USE_ENV_PROXY`                              | 模板为 `0`；设为 `1` 才启用 Node HTTP 环境代理 | 必须在 Node HTTP 初始化前进入启动环境；配合 `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY`                      |
| `HTTP_PROXY` / `HTTPS_PROXY`                      | 空；可信 HTTP(S) 出口代理                      | 对使用 Node fetch 的请求生效范围见第 8 节；不改变供应商端点白名单                                      |
| `NO_PROXY`                                        | 模板包含 localhost、回环地址、db/api/web       | 私有数据库/健康检查/同源内部服务不应意外绕经外部代理                                                   |
| `MEDIA_ADVANCED_ENABLED`                          | `false`；保留原件导入                          | 需要 Linux 处理环境；与普通图片上传的开关及预算分开                                                    |
| `MEDIA_PYTHON`                                    | 空；可信绝对 Python 路径                       | RAW/HDR 原生依赖的实际解释器；路径存在不等于 `nativeReady`                                             |
| `MEDIA_CONTAINER_MEMORY` / `MEDIA_CONTAINER_CPUS` | 覆盖文件默认 `4g` / `2`                        | Compose 容器总资源项；不由 API 读取为单文件预算                                                        |
| `DB_POOL_MAX`                                     | 默认 10，代码限制最多 50                       | 每个进程独立连接池；API、Worker、多个副本的总量需要共同预算                                            |
| `APP_ORIGIN` / `COOKIE_SECURE`                    | 精确 origin 列表 / HTTPS 安全 Cookie           | 包含实际网页 origin，无路径；同时用于变更请求和语音握手                                                |
| `TRUST_PROXY_HOPS`                                | 直接暴露 API 用 0；当前单层受控 Caddy 用 1     | 不能为了获取客户端 IP 信任任意转发头                                                                   |

`MEDIA_QA_PYTHON`、`MEDIA_QA_RAW` 仅供独立 QA 脚本，不是生产服务配置。生产媒体的 wall timeout、代理图像素和地址空间当前来自包默认值及 API 固定调用，没有公开的 `MEDIA_TIMEOUT` 或 `MEDIA_MAX_PIXELS` 环境变量；不要写不存在的变量并误以为已经放宽限制。

更改服务器开关、解释器或代理配置后应重启相应进程。模型配置由运营 API 持久更新，但已接纳任务的价格/参数快照不因后来改价而静默变化。

## 3. 数据库迁移、备份与恢复

### 3.1 迁移 8、9、10 的内容

| 迁移 | 新事实与保护                                                                                             | 运营影响                                                         |
| ---- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 8    | 协作会话/租约/预览/事件/命令收据；旧作品写入守卫；私有资源记忆、成员动态、账本 movement；V4 图层来源快照 | 旧保存可能因活跃租约返回 409；不能停掉新 UI 后假定旧接口可以抢写 |
| 9    | `assistant_model_configs`、助手 turn、语音会话、派发记录与候选                                           | 与原有模型配置分开；恢复必须核对独立文件发送日志                 |
| 10   | 媒体导入任务、原件对象/来源链接、空间在途媒体容量                                                        | 存储预算包含原件及独立副本；软删除不返还已保留原件容量           |

运行 `npm run db:migrate` 或 Compose 的 `migrate` 服务应用完整有序迁移；最新期望版本由清单导出。`doctor` 检查缺失和未知版本，而不是只看最大版本号。发布后不得修改已应用迁移的内容，也不手工把版本表改成 10；需要修复时追加迁移。

迁移前停止写入并备份。恢复旧应用二进制不是数据库降级方案；V4 表和触发器可能让旧写法被正确拒绝，必须在隔离恢复环境验证兼容性。数据库迁移版本与 Recipe 版本无关，V4 数据库继续保存旧 v1/v2/v3 配方。

### 3.2 需要一同保管的内容

- PostgreSQL：账户、权限、所有版本、派发/预占/账本、媒体对象链接和逻辑容量。
- `STORAGE_DIR`：规范化素材、缩略图、`media-v1/` 下原件/母版/瓦片，以及在途文件。
- `AI_JOURNAL_DIR`：旧任务日志和 `assistant/` 下独立 fsync 记录，不能用应用日志替代。
- 私有部署配置、凭据恢复方法、镜像/源码版本及原生依赖版本。不要把凭据装进公开验收产物。

下面是**停写窗口内创建新备份目录**的 Compose 示例，不是在线一致性备份方案。先按实际部署设置目录；已有同名目录时停止，避免覆盖旧备份：

```sh
set -eu
umask 077
xiutu_backup_dir="backups/v4-YYYYMMDD-HHMM"
mkdir -p backups
mkdir -m 700 "$xiutu_backup_dir"
docker compose stop --timeout 300 web api worker
docker compose exec -T db pg_dump -U xiutu -d xiutu -Fc > "$xiutu_backup_dir/database.dump"
docker compose run --rm --no-deps api tar -C /app/.data -cf - private ai-dispatch-journal > "$xiutu_backup_dir/private-and-dispatch.tar"
sha256sum "$xiutu_backup_dir/database.dump" "$xiutu_backup_dir/private-and-dispatch.tar" > "$xiutu_backup_dir/SHA256SUMS"
```

使用媒体覆盖部署时，上面的 Compose 操作应统一加相同的 `-f compose.yaml -f compose.media.yaml`，避免无意换回另一镜像配置。示例给 300 秒优雅退出窗口，实际应与已配置工作预算和观测到的收尾时间核对，不能保证所有上游都按时返回。先用隔离环境验证备份可读、所有引用文件存在、日志匹配，再重新开放入口。停止进程前应先停止新任务接纳；强制杀进程可能把已派发付费任务留为 unknown，这需要保留证据核验。

### 3.3 发送日志不一致时的正确处置

助手派发顺序是：**数据库标记提交 → 独立日志文件/目录 fsync → 再次锁定核验当前付费状态与权限 → 单次发送**。日志只含 ID、序号、摘要和时间，不存提示、图像或音频。相同记录已存在不表示允许重复发送。

恢复出的数据库缺少日志所指派发、摘要不同、连接记录回到 `prepared`，或日志格式/文件不可可靠读取时，付费入口以 `ASSISTANT_RECOVERY_REQUIRED` 阻断。应保持外发关闭，在隔离副本比对原始数据库备份、日志和供应商收据，确定丢失记录与实际调用；修复方案需保留审计与原始证据。不能为了启动服务删除日志、伪造派发或重新发送“看看会不会成功”。

普通 unknown 核验接口不会消除全局日志/数据库不一致。反过来，数据库标记存在而日志未发布可能发生在 fsync 前崩溃，不能直接证明已经发送。数据库和日志同时回滚或丢失的事实并非此机制都能检测；独立备份、持久介质与恢复演练仍是部署责任。

## 4. 助手与连续语音的配置、状态和结算

### 4.1 运营模型目录

通过运营端配置助手模型；对应 API 是 `GET /v1/ops/assistant-models` 读取目录、`PUT /v1/ops/assistant-models/:modelId` 更新单项。首次写入 `expectedHash:null`，后续必须提交读取到的配置哈希；409 时重新读取并确认，不覆盖另一位运营人员的修改。

必须指定 `provider:openai`、实际模型 ID、`enabled`、`operations` 和整数服务点 `unitCost`。操作只开放 `assistant-turn`、`realtime-voice`；语音模型必须在当前程序的已实现协议档案内。还可设置时长 30～600 秒、委派 1～20 次、输出 token 应用上限 256～8192，以及模型确实支持的图像输入、联网和推理强度。Realtime 输出进一步限制到 4096；不会给 GPT-Live 伪造它不支持的同名字段。具体字段以 [API_V4 §6](../apps/api/API_V4.md#6-contextual-assistant-and-continuous-voice) 为准。

应用当前为 GPT-Live 1 和 Realtime 系列分别实现协议适配；不能把用户口述的近似名称猜成可调用模型。使用 `/v1/assistant/models` 返回的实际档案和本账户真实权限选模型与音色。语音模型与后端助手模型需要分别启用；后端负责获准资源检索、图像推理和候选建议。

普通 turn 的 `unitCost` 是一个有界 turn 的固定服务点，语音的 `unitCost` 是一个明示时长块的固定服务点，有限后端委派包含在该块预算中。供应商 tokens/seconds 另外保存供核验；不能把服务点直接称作上游精确费用。本文不提供未经账单验证的价格数字。

### 4.2 状态不能混用

| 状态/事实              | 实际含义                                 | 允许的运营处理                                      |
| ---------------------- | ---------------------------------------- | --------------------------------------------------- |
| 语音 `prepared`        | 已预占，票据 60 秒有效，尚未确认连接     | 无发送证据的过期准备可释放；丢票据不自动补发        |
| `connecting`           | 已消费准备记录，正在准备/打开上游连接    | 失败也可能已发生调用；不能按“没听见声音”推断未消费  |
| `active`               | 上游已确认会话，持续处理音频/受限委派    | 监控时长、权限、心跳、背压；停用模型不直接退款      |
| 助手 `running`         | 已接纳 turn，可能正在审核或已派发        | 派发前/后必须结合持久标记和日志判断，不能只看状态名 |
| `completed` / `closed` | 应用完成其规定的结果或关闭结算条件       | 不是所有供应商最终发票已核对；保留原始用量事实      |
| `failed`               | 明确未发送、明确拒绝或已完成核验后的终态 | 以相应账本和审计判断释放/结算，不能仅按名称再退款   |
| `unknown`              | 存在可能已派发但结果/收据不确定          | 保留预占；真实证据核验后一次结算或释放，不自动重拨  |

GPT-Live 的终态核验检查最终 `session.closed` 使用量；Realtime 使用逐响应收据和受控关闭条件，没有假装存在相同的整会话最终收据。正常 WebSocket 关闭、已取得响应 token、应用点数结算、供应商最终账单应分别记录。

维护扫描每 20 秒检查遗留状态：普通 turn 超过 5 分钟无更新，语音 connecting/active 超过 45 秒无更新，或 prepared 已过期。派发证据存在时进入 unknown；只有可确认未派发的准备/任务才释放。扫描不依赖模型仍然启用。优雅停机等待升级中的握手、活跃连接和已派发委派有界收尾；不要把开发热重载或容器强杀当作无损会话迁移。

### 4.3 人工核验

`GET /v1/ops/assistant-reconciliation` 返回待核验元数据，不授予私人提示或图像读取权。处理入口为 `POST /v1/ops/assistant-reconciliation/:kind/:recordId`，kind 为 `turn` 或 `voice`，提交 `resolution:release|settle`、原因和真实证据引用。记录锁与 hold 保证一次处理；重复处理返回 409，应读回终态，不再发一次赠额替代核验。

普通队列 AI 仍使用原有核验入口。仅 queued 且无发送证据的任务可由任务本人或有权空间管理员取消；running/unknown 不能借取消通道退点。用户拒绝已完成图片或文字候选，不改变已经发生的供应商工作。

### 4.4 单实例与持久化边界

普通 turn 每个用户最多一个在运行，准入每小时 30 次；语音每个用户最多一个 prepared/connecting/active，准入每小时 12 次。API 实例最多 32 个活跃/升级中语音连接，另有输入速率、消息大小、出站背压和委派/响应预算。

连接票据的数据库状态持久，但准备阶段明确分享的图像快照、实际 socket、音频播放进度和部分短期状态在内存中。带图准备遇到重启/请求被路由到另一 API 实例时可能无法使用；已接通语音不能在重启后无缝恢复。初期按单 API 实例部署；多实例需同源 WebSocket 路由粘性、共享私有卷、相同持久日志和新的全局准入设计，不能仅把副本数改大。

## 5. 服务点、运营调额与使用量

自动月度权益、个人钱包、团队钱包、套餐目录和人工调额保留原有接口。用户月度权益按亚洲/上海自然月、用户唯一发放；创建更多团队不重复赠送个人权益，团队不会自动借用个人余额。

运营通过 `POST /v1/ops/adjustments` 以目标 `spaceId`、整数正负点数、幂等键、原因等受校验字段调整额度，后台记录操作者与调整来源。不要直接更新数据库余额，也不要用人工赠额掩盖 unknown 状态；调额和付费核验是不同业务事实。在线支付仍未启用，套餐目录不等于自动到账能力。

`/v1/usage` 提供本人钱包或当前空间用量，`/v1/ops/usage` 提供运营授权聚合；AIJob、AssistantTurn、VoiceSession 关联同一额度流水。统计分别展示 issued、held、consumed、released、expired、adjusted，单位是服务点。held 聚合是预占流量，当前冻结余额另看完整钱包。释放过期批次时同时记录释放和到期，旧历史不能准确恢复的金额明确标为未知。

查询按亚洲/上海日/月聚合，明细和 CSV 有界分页；CSV 下一页在响应头中，不能只导出第一页后称为完整账单。运营审计入口可查配置、状态和调额变更，但不自动获得私有照片或个人记忆。新旧接口及参数详见 [API.md](../apps/api/API.md) 与 [API_V4.md](../apps/api/API_V4.md)。

## 6. 团队、资源和协作的运维边界

### 6.1 成员离开与资源保留

个人空间和团队空间使用同一数据模型，归属决定 ACL 和钱包。成员离开、被移除或实际角色变化时，同一事务撤销其房间会话、租约、临时预览；离开团队取消任务负责人关系。团队已经拥有的素材、文档和不可变版本继续保留，不按上传者是否仍在团队删除。

最后一位 owner 不能直接移除。需要交接时，用团队所有权转移接口核对当前 owner 与既有活跃目标成员，原 owner 转为 admin。个人空间不能借该接口变成别人的空间。权限变化后后续读取、协作轮询和付费派发重新校验；语音按有界周期及委派前检查撤权，不承诺网络上已经传出的字节可收回。

资源检索同时考虑当前成员和有效分享授权；运营身份不增加私有素材行。长期标注是每个用户自己的 `ResourceMemory`，有独立版本、可删除，默认不发给团队或 AI。来源权限失效后，用户仍可删除自己已有的记忆。明确选择“使用个人记忆”也只在本次获准上下文内读取有权资源，不改变其共享权限。

独立复制需要来源读权、来源复制政策/授权和目标编辑权限。保留原件只能从明确合法的源素材链接复制，不能靠相同代理图哈希取得别人原件。已完成的独立副本不会因为以后撤销来源授权而消失；新复制仍受当前权限限制。历史版本、讨论、任务和团队成员不是项目复制的默认内容。

### 6.2 长轮询与租约成本

| 限制                        | 当前数值                      | 运维含义                                                    |
| --------------------------- | ----------------------------- | ----------------------------------------------------------- |
| 房间会话 / 目标租约         | 60 秒 / 30 秒，建议 10 秒续期 | 掉线暂时阻塞会到期；不应人工直接清表抢锁                    |
| 游标 / 预览最小更新间隔     | 250ms / 300ms                 | 高频 pointermove 要合并，避免客户端把每个像素移动都变成请求 |
| 长轮询最长等待 / 跨进程检查 | 20 秒 / 350ms                 | 不是 20 秒才更新；每次等待内部会多次查权限/状态             |
| 单 API 实例并行轮询         | 每用户 8、总计 128            | 429 后按返回间隔退避；不是分布式全局限额                    |
| 单作品会话                  | 总计 24、每用户 4             | 多浏览器标签会占用真实会话名额                              |
| 每会话租约                  | 8                             | 结构、几何、V4 修复等使用文档级租约                         |
| 预览容量                    | 单操作 128KiB、单作品 512KiB  | 临时态不创建修订，也不扣 AI 点数                            |
| 传输事件保留                | 每作品最近 1000 条            | 旧游标回退到最新权威快照；持久修订与命令收据另外保存        |

长轮询没有持锁事务等待，但每个活跃等待者在没有本机唤醒时仍约每 350ms 执行一次数据库检查，每轮不止一条 SQL。这个间隔是代码节拍，不是已测 QPS 或时延 SLA。连接池和数据库 CPU 应按真实并发监测；增加 API 副本会放大独立轮询上限及查询成本。当前 PostgreSQL 有 NOTIFY 发出，但跨进程可用性依靠轮询补齐，没有专用 LISTEN 消费集群。

反向代理应允许 20 秒长轮询及持续 WebSocket，不把业务请求短超时误当成应用掉线。旧保存、历史恢复、AI 替换与加层都受相同租约数据库守卫；`COLLABORATION_LOCKED` 应让用户结束/等待当前编辑，不能自动重试整配方覆盖。TTL 清理在房间访问时执行，并非全库持续清扫。

## 7. 媒体原件、母版、代理图与实际预算

### 7.1 两条导入链与访问权限

普通上传仍规范化为 sRGB PNG，不保留源容器。高级导入是独立、明确启用的接口：逐字节保存原编码，再生成方向/颜色归一化的 uint16 SDR 母版、RGBA8 代理图和可选查看瓦片；HDR 范围另有线性 EXR。不能把“普通上传不保留原件”泛化为 V4 所有导入都丢失原件，也不能把高级导入的保留能力套给旧素材。

所有原件、母版、DZI 和瓦片通过对应 Asset 的当前项目/分享 ACL 读取，不是公开 UUID 下载链接。普通素材与原件的来源链接不同，代理图字节相同不授予另一原件权限。原文件可能含 EXIF/GPS/ICC；原件下载会保留这些原编码内容。团队是否允许上传/分享含敏感元数据的原件，需要用户在明确项目范围内决定；当前没有完整的逐标签剥离/编辑控制台。

浏览器编辑绑定代理的实际 RGBA8 像素和哈希。母版导出 `png16/tiff16/jpeg/webp` 是格式转换，响应明确 `X-Editor-Recipe-Included:false`，**不会自动把浏览器 V4 配方重放到高位深原尺寸**。大图瓦片查看也不等于 200MP 像素编辑。

### 7.2 接口和处理预算

| 项目                          | 当前生产路径预算                                 | 说明                                                                |
| ----------------------------- | ------------------------------------------------ | ------------------------------------------------------------------- |
| 原编码上传                    | 最多 512MiB，单块最多 4MiB                       | 连续分块；只有完全相同的已确认字节可幂等重传                        |
| 同时活跃导入                  | 每用户 1、数据库范围最多 4                       | 正在取消但尚未释放 reservation 的任务仍占名额                       |
| 媒体执行槽                    | 每 API 进程 1 执行、最多 8 等待                  | 并非分布式作业队列；导出也共享包级处理槽                            |
| 普通静态 raster               | 最多 200,000,000 像素，单边最多 65535            | 仍受实际 codec、文件大小、时间和内存约束                            |
| Camera RAW                    | 全传感器最多 64MP                                | LibRaw 原尺寸显影，浮点母版按瓦片行写入                             |
| EXR / Radiance                | 数据窗口最多 50MP                                | OpenImageIO，色域、通道及资源限制分别生效                           |
| PSD                           | 最多 16,777,216 像素、128MiB、256 元数据节点     | 读取已存合成图及有界层摘要，不是可编辑 PSD 图层往返                 |
| 生产导入代理图                | 最多 4,194,304 像素                              | 与原件/母版尺寸分开                                                 |
| 生产导入隔离执行 wall timeout | 180 秒                                           | 当前 API 未暴露环境变量放宽该值；不等于上传/排队/发布全过程截止     |
| API 母版格式转换执行          | 45 秒                                            | 每 API 实例最多 2 个、每用户最多 1 个转换；不含等待执行槽和文件下传 |
| 已准备的浏览器母版附件        | 60 秒内领取一次                                  | 同一会话和当前素材权限。每实例最多 2 份、每用户 1 份。领取后由浏览器直接流式下载 |
| 解码进程地址空间              | 每进程默认 4GiB                                  | 与容器总内存分开；Node/Python 的内存不能相加忽略                    |
| 其他解码限制                  | JS 堆 512MiB、单文件 2GiB、FD 128、瓦片最多 8192 | 不是总目录磁盘限额或文件系统/网络沙箱                               |

接纳前还检查临时磁盘余量：至少输入大小的两倍再加 2GiB；这个门禁不是完整任务峰值磁盘保证。原件、母版、代理图、瓦片、解码临时文件和备份可能同时存在，应监测真实磁盘余量。

空间存储账户先预占输入大小；发布时同事务释放预占并计入实际保留文件树和代理素材容量。原件独立复制按目标空间的独立留存链接计费，不能用物理字节去重跳过租户容量。运营可通过现有存储策略 API 调整 `maxBytes/maxAssets`，需要 CAS 版本和原因；这与服务点调额分开。

取消处理可能返回 `cleanupPending:true`。远端/正在执行的任务没有确认停止前，reservation 与工作目录继续保留，反复取消不能提前清空容量。执行心跳每 10 秒；维护每 30 秒检查上传 30 分钟或处理/遗留取消 5 分钟无更新的任务，进行权威状态复核与清理，而不是自动重新解码。已 ready 的导入不能靠取消删除原件。软删除仍占留存容量；目前没有公开物理 GC，不要按孤立文件名自行批量删除。

### 7.3 已有证据与不能推导的结果

[v4-media-native.json](verification/v4-media-native.json) 记录了 2026-11-10 的真实 Linux 原生执行、依赖版本、源文件摘要及逐例结果。实际相机 RAW 只有一个 NEF 样本；EXR/Radiance 使用已知浮点梯度和 alpha/错误色域夹具，不能推广为所有相机与色彩空间都通过。

200MP 案例是 **20,000×10,000、uint16、重复行的非均匀渐变 TIFF**，高度可压缩。它完成原件、母版、代理图、DZI 的导入链，另验证处理中取消、超时清理；大图 PNG 导出在实际出现流式 ICC 中间文件后被主动取消，验证清理，**没有宣称完整 200MP PNG 导出成功**。

| 执行路径                            | 时间预算                    | 代理图预算       | 如何解释结果                                        |
| ----------------------------------- | --------------------------- | ---------------- | --------------------------------------------------- |
| 独立 `media-verify.ts` 普通成功案例 | 600 秒                      | 1,048,576 像素   | QA 专用配置，不能冒充默认生产请求                   |
| 生产高级导入 API                    | 隔离执行 180 秒             | 4,194,304 像素   | 文件相同也可能有不同内存/时间结果                   |
| 200MP ICC 导出取消案例              | 包调用 180 秒，另有受控取消 | 不生成新编辑代理 | 证明特定处理阶段可取消清理，不证明完整导出耗时      |
| 生产母版导出 API                    | 转换执行 45 秒              | 不重放浏览器配方 | 需要按实际源图及导出格式单独验收；另有排队/下传时间 |

`getMediaCapabilities.nativeReady` 只证明指定解释器可以真实 import 固定依赖；`available` 只证明当前处理环境门禁通过。它们都不代表所有文件/预算已经成功。单元测试、原生 QA、HTTP 导入集成和生产容器限制下的测试应分别保存证据。

复现原生 QA 前先安装固定依赖，准备有权使用的相机样本，并保护现有 `artifacts/media-v4` 输出；脚本会重建自己的同名 QA 目录：

```sh
python3 -m venv /absolute/private/media-venv
/absolute/private/media-venv/bin/pip install -r packages/media/native/requirements.txt
MEDIA_QA_PYTHON=/absolute/private/media-venv/bin/python \
MEDIA_QA_RAW=/absolute/authorized/sample.NEF \
node --import tsx scripts/qa/media-verify.ts --large
```

脚本不自动下载样本或调用 AI，输出 `artifacts/media-v4/evidence.json`。原生格式、颜色解释和未实现格式详见 [media README](../packages/media/README.md)。

## 8. 服务器出口代理与大陆访问

必须分别检查两段网络：**用户浏览器 → 网站**与**网站服务器/Worker → 供应商**。服务端出口代理只影响后者，不能修复前者的 DNS、域名备案/接入要求、TLS、网站机房线路、素材下载或手机运营商路径。静态资源、模型 WASM 和业务 API 同源减少外部浏览器依赖，但不等于大陆可用性已经通过。

### 8.1 HTTP fetch 与语音 WebSocket 分开配置

| 调用                                                 | 出口配置                                                                          | 范围                                                             |
| ---------------------------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Responses、Images 及其他使用 Node fetch 的服务器请求 | Node 启动时 `NODE_USE_ENV_PROXY=1` 加 `HTTPS_PROXY`/`HTTP_PROXY`、正确 `NO_PROXY` | 不替换官方端点、不接受浏览器任意代理 URL                         |
| 连续语音到供应商的 WebSocket                         | `ASSISTANT_EGRESS_PROXY`                                                          | 当前用 HTTP CONNECT agent，仅语音上游；不控制 Responses 后端委派 |
| 浏览器到同源网站/API/语音桥                          | 用户实际网络与部署入口                                                            | 不受上面两项服务器出口变量直接控制                               |

根目录 `npm start`、`npm run worker:ai` 使用 Node 的 `--env-file-if-exists`；`npm run dev` 在生成子进程前加载环境；Compose 在进程创建前传入 `env_file`。这些是当前支持的启动入口。仅在已经运行的 Node 中再用 dotenv 设置代理变量，不保证能重新初始化内置 HTTP 代理；直接使用其他启动方式时应由 shell、systemd 或容器注入启动环境。改代理后重启需要它的 API/Worker。

`ASSISTANT_EGRESS_PROXY` 只接受受控的 `http://` 或 `https://` 代理根地址，不接受 SOCKS、SS 订阅字符串、任意路径或碎片。JMS 若提供的是 SOCKS/SS，需由部署者另行配置允许用途的本机 HTTP CONNECT 桥，再分别接到 HTTP 和 WebSocket 两个出口；本项目不解析订阅、不配置代理客户端，也没有验证用户节点是否支持该用途。代理配置失败不会自动切换另一个模型或偷偷用直接出站重试付费请求。

代理认证信息只放服务器私密配置，禁止回传前端或写进请求 URL/公开日志。对本地与 Compose 内部服务正确设置 `NO_PROXY`。解码子进程不继承 API 密钥或代理密码；原件解码不应依赖外部网络。

### 8.2 JMS 的当前结论与验收方法

目前只有服务网站信息，未得到并核验实际节点协议、连接配置、并发/流量限制、适用条款和出口地区。因此只能给出“可在支持 HTTP CONNECT 的受控桥接前提下接入”的技术路径，不能报告订阅已可用、已获供应商地区许可或已完成生产稳定性验证。

正式验收先区分 DNS/TLS/连接建立、长轮询、WebSocket、上传/下载、审核、模型派发和账本结算。网站段应覆盖三家大陆运营商、Wi-Fi/移动网络、目标手机/平板/电脑及弱网重连；供应商段记录真实账户允许的模型、区域与网络路径。HTTP 通了不代表持续 WebSocket 通了，静态首页通了不代表大图上传或 AI 可用。记录成功率、p50/p95、断线原因与 unknown 比例；在取得明确授权前，不用循环真实生成测试网络而制造费用。

## 9. 发布与日常维护的证据要求

发布前至少确认实际数据库迁移、真实存储卷挂载与 fsync、当前模块 readiness、模型/审核配置、Origin/Cookie、反向代理长请求与 WebSocket 行为。保留对应源码/镜像版本的测试证据，外部账户、短信实收、真实麦克风和生产恢复需要各自验收记录。

日常关注队列等待、unknown 数量、个人/团队余额、逻辑留存与实际磁盘余量、媒体 reservation、轮询 429、租约冲突、语音心跳和背压。业务审计不替代技术指标；技术日志不得收集原始麦克风、私有照片或密钥。未完成导入、缩略缓存、历史事件和派发日志的维护都应尊重引用与保留语义，不能用通用“清空旧文件”脚本代替生命周期管理。

本手册不新增服务器或模型价格，不把促销/free tier 写成长期预算。应以自己的供应商账单与实际存储/带宽/审核使用量核算；服务点策略和系统可用性分别验证。最终六轮全仓检查、容器 CI 和浏览器验收的具体结果以本轮对应提交的验证记录为准，不用文档中的命令存在代替执行证据。
