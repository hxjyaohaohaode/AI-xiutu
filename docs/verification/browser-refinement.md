## 实际完成的工作流

### 1. 自由构图与双向色彩

在桌面导入建筑 JPEG：通过控件将原图区域裁成 347×281，右转后画面尺寸为 281×347；再把工具面板停靠到右侧，在旋转画面上拖动右下裁切手柄，原图裁切区域变为 390×242、输出方向为 242×390。边缘拖动与像素数值联动。

继续将宽、高设为 1×1，打开 PNG 导出并点击下载；界面生成体积提示，但浏览器下载接口返回 `Download ... failed`，没有取得可读文件。因此不能声称本次浏览器下载文件已成功落盘、重新解码或逐像素复验。随后恢复原始裁切并转回 640×427。

实际调节全局饱和度到 -55.5，绿色分色的色相到 -18.2°、明度到 +24.5；连续选色器接受 `#FF000080`，RGB 读数为 255/0/0，alpha（不透明度）约为 50.2%。这一色谱是参考色选择器；照片调色通过整体、分色、分级和选区参数执行，不能把选中参考色等同已替换照片颜色。

### 2. 两个独立的人物精修区

导入人像 JPEG，从顶层“美颜”添加第一个人物精修区，把柔化设为 45；再添加第二个区域，第二个的柔化仍为 0。在图上把第二个区域中心从约 (494,459) 拖到 (586,560)，再切回第一个，柔化仍为 45。两个区域参数没有互相覆盖。关闭蒙版覆盖后，整张人像在可用空间内显示为约 568.31×666 CSS 像素。

该操作只证明手动人物区域的独立参数和移动，不证明自动识别人脸、自动分割皮肤、多人物关键点、妆容识别或五官形变。界面明确提示这些能力尚未接入。

### 3. 自由曲线

本轮桌面操作中新增中间控制点，并通过数值及拖动修改输入/输出；实际曲线和图片随之改变。最终手机 390×844 视口中再次导入花卉 JPEG，新增控制点后，将中间点从 127.5→127.5 调为 127.5→95.2，可访问性读数和曲线同步更新。

滑条当前按其声明步长接收数值；95.25 不在该滑条的 0.1 步格内，被控件拒绝，95.2 正常提交。这不代表所有数值都能以任意无限精度通过滑条设置。实际连续手势归属、晚到事件、第二指针、切换图像/通道以及旧预览不能回滚新编辑等情况，另由有针对性的自动测试覆盖，未把所有这类手势宣称为真实触屏实测。

### 4. 草图与 AI 参考联动

在 1440×900 视口打开草图板，用鼠标实际画出一条笔画。撤销、清空、放进编辑器和作为生图参考按钮随真实内容启用。点击“作为生图参考”后，AI 面板进入生图模式，显示“1 张参考”。未登录且无适用模型时，模型选择与生成发送不可执行，没有伪造生成结果。

在 390×844 视口切换语音入口，界面说明先录音、再确认发送识别；当前 HTTP 预览显示不支持录音并提示使用 HTTPS / 支持麦克风的浏览器或文字输入。本次没有录到真实音频，也没有调用付费 ASR。

## 六种真实应用视口

开发验收页 `qa-responsive.html` 用独立 iframe 让应用真实执行媒体查询；外部验收页为摆放画框可以滚动，应用自身的根页面没有溢出。它不是物理设备模拟器，也不模拟触控性能、内存和移动网络。

| 应用视口 | 本轮实际导入和检查 | 根页面测量 |
|---|---|---|
| 320×700 | AVIF 960×640；色彩面板；把底部面板手柄下拖约 80px 后，更多空间回到图片，面板内部独立滚动 | client / scroll 均 320×700 |
| 390×844 | 花卉 JPEG；曲线新增点、小数微调；AI/语音未就绪状态 | client / scroll 均 390×844 |
| 768×1024 | WebP 2400×1600；侧边局部编辑与添加选区入口 | client / scroll 均 768×1024 |
| 844×390 | 花卉 JPEG；明暗面板，侧边布局与底部工具栏同屏 | client / scroll 均 844×390 |
| 1024×768 | PNG 2400×1600；细节面板；预览约 630×419.83 CSS 像素 | client / scroll 均 1024×768 |
| 1440×900 | 建筑 JPEG；自由构图手柄；草图到 AI 参考图 | client / scroll 均 1440×900 |

另有主桌面视口 1363×936 的完整建筑与人像实操。1024 平板和主桌面检查照片本身至根节点的计算样式，未出现 `filter` 模糊；高斯显隐动效应用在工具、统计图和文字提示，不以模糊照片来掩盖渲染状态。

## 浏览器异常与限制

开发过程中修改 `useEditor` 的 Hook 结构曾触发 Vite 热更新的 Hook 顺序错误；重新加载后继续完成上述工作流。最终日志中仍能读到这条历史开发记录，不能据此声称整段开发过程“零控制台错误”。响应式画框通过新页面加载完成检查；另见自动化类型检查、构建和真实 SQL 回归结果。

浏览器扩展自身也记录了向扩展发送元数据失败，这些日志的来源为 `chrome-extension://`，与应用业务错误分开。整页截图和下载取回接口各出现过超时/失败；仅列出实际保存并可读取的截图，不虚构下载字节复验。

本轮未在浏览器登录，因此个人/团队切换后的持久化、成员邀请、运营设置、额度管理等不算作本轮浏览器端到端验收。对应的鉴权、数据隔离、并发保存、额度、HTTP 契约由实际 SQL/API 测试覆盖。没有进行真实短信、收费 AI、自动人像检测、真实麦克风、JMS 出口、三网或生产支付实测。
