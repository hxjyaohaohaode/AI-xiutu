## 2. 修复后应长期保持的不变量

1. **来源不能由浏览器赋权。** 已知云素材跨项目必须通过受授权的复制；复制被拒绝时不将同一下载文件偷偷作为新上传。未知本地文件的历史来源无法可靠识别，系统不承诺绝对防复制。
2. **保存配方的每个来源都可解析。** 完成云端保存前，所有本地临时层都转换为同项目真实素材；已存在的外部云层通过授权复制。缺失、删除、外部 URL 和跨项目 ID 均拒绝。
3. **源与修订不可拆开更新。** AI 替换和历史恢复追加带正确源的完整快照。旧版本仍能读自己的原图，不把旧蒙版套到今天的源图上。
4. **采纳只是用户决定，不是第二次生成或结算。** `reject/fork/replace/layer/apply-plan/save-text` 有不可变决定；幂等重试不重复产生分支和账本。拒绝已完成结果不伪称供应商退款。
5. **源政策与已完成副本有明确边界。** 新复制始终检查当前政策；已提交同键重试只读取已有独立目标并检查目标编辑权。目的副本删除后同键返回冲突，新键才能明确重建。
6. **容量是事务事实。** 同空间不同项目的上传/生成/复制都更新同一容量行。任何中途失败与最后授权检查失败一起回滚素材、请求、审计和计数。不同幂等键复用同一有效副本不重复计数。
7. **保留量不等于物理磁盘占用。** 每个素材记录计其规范化字节；共享不可变文件的多个副本仍各计一次。软删除不释放容量；没有自动垃圾回收。
8. **运营只能获取其被授予的权限。** 运营可配置容量、模型和额度，但不能借配置接口下载私图或读取配方/文案。新增审计保留标识、哈希和动作，不复制私人内容。
9. **过时异步结果不覆盖新操作。** 下载、分层解码、导入和保存分别检查请求/源身份；加载中发生新的编辑就保留编辑。先成功上传的素材即便后续版本冲突也保留在目标项目供用户处理。
10. **配置、契约和执行器要分开说明。** 模块目录不自动带来算法或权限；人像资产是否加载成功、供应商是否真实可用、支付是否接通都不是目录可替代的验收事实。

## 4. 仍需部署验收或后续实现的具体边界

- 原生 PostgreSQL 多连接并发、部署重启/恢复和跨进程文件卷一致性须按生产拓扑实测。
- 运营容量的GET/PUT API可用，但本次没有新增专门的网页容量配置面板。
- 默认每空间1 GiB/1000条属于初始运营限制，可调整；历史超限数据不会被删除。永久回收和迁移到对象存储须建立显式保留流程。
- 外部生成前没有按未来未知字节数预占空间。收费调用成功而发布遇到容量不足时保留发送证据与核验状态，不把存储错误解释为“供应商免费失败”。
- 浏览器的8192px单边和16.8MP工作台限制与服务端规范化/保留上限分别存在；不能把较大的服务端上限当作手机可以编辑的保证。
- 审查和自动断言不替代真实照片质量、屏幕布局、网络、供应商账号与地区可用性验收。
