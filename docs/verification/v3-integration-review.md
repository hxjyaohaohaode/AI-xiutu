# V3 集成复核：实际发现、修复和证据边界

本记录对应本次 V3 开发，最终冻结代码与六轮全仓门禁见 [总验证](../VERIFICATION.md)。复核包含源码路径阅读、真实 SQL/API 测试、原生模型推理、真实浏览器操作；没有把这四者互相替代，也没有声称穷尽所有输入、硬件或执行路径。

## 1. 集成中真实发现的问题

| 问题 | 修复及验证方式 |
| --- | --- |
| 下载的人体模型曾只有 3,207,168 字节，先前摘要也对应这个不完整文件 | 取得官方完整 5,777,746 字节文件；准备脚本同时检查长度、SHA-256、ZIP 目录/结束记录和必要模型项。随后完成真实 CPU 推理，而非只验证文件存在。 |
| 真实半身照片的不可见腿部关键点可在画面外，导致整份包含有效面部/肩颈的结果被拒绝 | 身体数据接受有界外推范围；每项工具继续要求自己的必需关节可见且在图内。不可见腿部不会因此开启美腿。 |
| 当前云端浏览器的 Web 图像输入缺少可用 WebGL 2，模型 CPU 委托也不能消除这一依赖 | 分析 Worker 先做图形能力检查，60 秒超时并支持取消；失败显示真实原因。原生 CPU 成功与 Web 路径失败分开记录；允许导入绑定当前图像的真实分析结果继续精修。 |
| HTTP 开发预览下直接使用 `crypto.randomUUID()`，实际液化动作发生异常 | 统一使用现有安全 UUID 工具及 `getRandomValues` 后备；没有安全随机源则明确失败。修复后真实浏览器液化产生一笔，撤销为零，重做为一。 |
| 图像已显示但导入尾部尚未结束，用户刚打开的工具面板会被晚到的关闭动作收起 | 在开始导入时关闭旧面板，删除完成后的迟到关闭。再次导入后选择工具及 AI 面板保持打开。来源解码/版本身份保护仍独立存在。 |
| 大面板只根据工作区外框计算剩余空间，未扣除照片栏、工具栏和拟合留白 | 统一计算真实照片安全区。窄屏实测进一步发现自动叠放会遮住主体；停靠“画面自动让位”必须保留避让，紧凑区提供收起看全图并恢复原尺寸的操作。最终观察见浏览器记录。 |
| 导入新图期间，交付入口可能生成旧图，旧编码又晚于来源切换完成 | 交付/顶栏统一来源加载门禁；异步完成前后核对来源、配方、任务代次和存活状态，过时结果不分配对象URL，已准备链接点击前再校验。19项导出/来源/动效定向回归与Web类型检查通过。 |
| 预览的源图预算与变换后输出预算可能不同 | 预览按实际输出维度及上限缩放；源图不变，不能仅限制解码却在旋转/放大时分配超大输出。实际 Worker 与预算用例覆盖。 |
| 绘制中第二触点可能触发平移并改变坐标基准 | 编辑指针与视口手势建立明确所有权；多触点到达取消本次尚未提交的编辑，所有触点结束后才恢复。已做状态机与坐标测试，尚未做真实多指硬件验收。 |
| 旧建议摘要只看 v1 基本参数，会漏掉 v2/v3 改动 | 数值与结构摘要覆盖现有注册字段，保留对象稳定排序和数组顺序意义；不把“没有基础参数变化”当成没有编辑。 |
| 全部供应商停用时 worker 同时停止了 stale 任务维护 | 统一维护独立于可派发能力；旧运行任务进入 unknown 并保留发送与额度证据。不能用重新开启供应商作为恢复前提。 |
| 已有发送证据的 queued 任务可能先遇到撤权/停模而释放预占 | 两条 claim 路径先查派发证据；不明状态进入核验，不能假定未调用。取消亦在同一任务行锁内判断。 |
| `doctor` 仍接受任意版本 ≥2，不能识别当前迁移缺失 | 迁移执行与诊断共享有序注册表，要求 1–7 连续齐全，拒绝空表、缺洞或未知更高迁移。真实 CLI 用当前数据库验证。 |

## 3. 真实人像实验

使用官方 MediaPipe 1.2.2 原生 CPU 路径，三张有明确来源的公开照片经规范化后推理，再将真实分析数据输入产品 `@ai-xiutu/portrait` 与 `@ai-xiutu/editor`。

- Hopper：512×600，478 面部点及 33 身体点；36 面部控制、4 个可见关节对应的身体控制可用。
- MediaPipe portrait：820×1024，478 面部点及 33 身体点；36 面部控制、7 身体控制可用。
- MediaPipe pose：1000×667，没有检出有效脸部，33 身体点；10 身体控制可用。未把缺失人脸补成假目标。
- 总计 46/46 控制产生实际像素变化；36 个双向控制的正负结果不同；46 项全幅/分块逐字节一致，18 项检查蒙版外像素不变，46 项确认原图摘要不变。

这证明这三份真实分析输入接入了实际算法，不证明自动识别普遍准确或达到商业软件画质。已查看原图、定位图、对照接触表和局部效果；没有标注真实边缘 ground truth，没有计算人群准确率，也没有在手机上测量这些耗时。模型运行警告、CPU环境、图片/模型/代码 SHA 和逐项结果完整保留在 [原生记录](v3-portrait-native.json)。

## 4. 明确未验收或未实现

- 云端 Chrome 没有完成 Web 自动人物推理；已完成原生 CPU 推理与浏览器导入真实结果后的精修链路。
- 实际完成 PNG/JPEG/WebP 浏览器编码，下载工具均未取得可读文件；没有声称下载文件重新打开、逐像素一致或所有终端保存成功。
- 浏览器本轮未登录，未实际走团队/运营页面的用户级端到端流程；这些权限与数据链路由 SQL/API 套件覆盖，不能冒充 UI 实测。
- 没有发送真实短信、付费模型请求或支付，没有使用用户代理凭据；大陆三网、生产 HTTPS、Safari/Android 真机、麦克风和低端设备长时负载仍须部署验收。
- 没有自动痘斑/皱纹检测与神经修复、发丝重建、三维人体重塑、实时视频美颜、CRDT 同笔画协作、任意图层交错/PSD 往返或完整高位深/ICC/HDR 工作流。
- 78 个逻辑动效角色有分别声明的三端参数，重复组件使用对应角色；这不是每一个 DOM 实例独一无二，也不是逐帧/逐像素无误差的视觉证明。
- 六轮门禁覆盖全部**现有**测试和编译项目，不是六次人工逐行阅读，不是穷尽无限输入路径；任何总数必须从实际日志提取后报告。
