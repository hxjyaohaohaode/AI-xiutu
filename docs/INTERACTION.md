# 内容工作台：交互基线与能力边界

本文描述本轮已经落入源码的交互，而不是远期功能清单。具体数值定义以 `packages/editor/README.md` 为准，服务器和外部任务以 `apps/api/API.md`、`packages/multimodal/OPENAI.md` 为准。浏览器实测和本轮五次完整自动化检查见 `docs/VERIFICATION.md`；此前初版记录已单独归档到 `docs/verification/initial-baseline.md`，不充当本轮新增交互的验证证据。

## 1. 一个作品，按需出现的工具

默认视图只保留作品、顶部动作和底部工具。美颜、明暗、色彩、曲线、构图、局部、细节、记录与 AI 共享当前作品和配方。选中项使用中性色面的微小色阶差、字重和图标状态表达；工具内容内部不堆叠一层层描边卡片。工作面板的外边界、当前裁切范围和曲线坐标网格有各自的实际用途，不能为了“少框”移除必要的操作反馈。

工具选择与参数不是同一层：先选工具族，再选色段、人物区域、通道或高级设置。默认只展示当前任务必需的内容。参数以滑条为主，点击当前数值才展开精确输入；重置可单项进行。编辑器 PrecisionRange 的键盘方向键按字段步长改变，Shift 提高步幅，Alt 精调；必须为整数的像素、颗粒尺寸和种子不会被 Alt 变成非法小数。AI与运营使用独立的范围/精确值控件，不把这组修饰键语义泛化到所有输入。

### 布局责任

| 内容 | 桌面                                  | 平板                             | 窄手机 / 短横屏                                                 |
| ---- | ------------------------------------- | -------------------------------- | --------------------------------------------------------------- |
| 作品 | 按可用工作区整体适应，支持放大/平移   | 保留作品与单个当前工具           | 减去底部面板/工具栏后重新计算适应尺寸                           |
| 面板 | 拖标题移动，8 边角缩放，左右/底部停靠 | 根据剩余空间独立约束尺寸         | 小于760px宽时固定底部调高低；较宽的短横屏保留停靠选择并约束高度 |
| AI   | 状态、当前消息与输入在清楚的层级中    | 单一主滚动区                     | 正文紧凑，状态与输入优先，参数逐级展开                          |
| 列表 | 多列素材网格与分组筛选                | 筛选随宽度换行，保留授权空间范围 | 素材为两列缩略图并通过服务器游标载入更多；文档/任务为条目列表     |
| 触控 | 鼠标可细调                            | 控件触达区独立于图标             | 图标/文字可更紧凑，但关键触达区不随文字一起缩小                 |

布局是设备偏好，图片尺寸是文档数据，二者不能混在同一对象里。缩放、移动面板不修改作品；裁切才改变导出区域。布局有边界夹取和恢复默认，避免用户把面板拖到永远找不到的位置。这里只对实际检查过的视口作验收声明，不把媒体查询的存在写成所有设备已验证。

## 2. 多局部与分人精修

新 v2 配方的 regions 数组最多包含 8 个独立区域，迁移保留的旧版 local 阶段另计；每个区域有独立名字、蒙版、启用状态、强度和 13 项基础调整。可切换、复制、排序、隐藏、删除并撤销。切换当前区域只改变正在操作哪个对象，不清空其他区域。

| 选区     | 直接操作                   | 精调                                    | 适用边界                              |
| -------- | -------------------------- | --------------------------------------- | ------------------------------------- |
| 径向     | 点中心、拖中心或两个轴端点 | 中心、半径、羽化、反选                  | 手工补光、人物/物体局部               |
| 线性渐变 | 拖起点/终点                | 两端坐标、平滑、反选                    | 天空、地面、方向光和过渡              |
| 多边形   | 拖点、双击最近边加点       | 点坐标、删点、羽化                      | 任意手工轮廓，最多 64 点              |
| 笔刷     | 直接画添加/减去笔触        | 半径、羽化、流量                        | 精细选区；有点数/笔画预算             |
| 栅格 RLE | 从已验证配方读取           | 强度、反选                              | 可表达逐像素权重；没有无限栅格画板 UI |
| 颜色范围 | 从原图预览取色后应用       | 连续色相中心/半宽、饱和与亮度范围、羽化 | 全图匹配颜色；不是自动皮肤识别        |

最小笔刷半径为 0.5 个原图像素，硬边并对准像素中心时可限制一个像素的写入。大笔刷继续使用连续坐标。画面预览可能缩小，因此“原图一像素”并不保证在适应全图的显示比例下肉眼可见；最终实际像素由同一配方的原尺寸导出计算。

区域顺序有意义：后一区域读取前一区域的结果。复制必须检查全配方的笔刷总点数与 RLE 总游程数量，失败应显示原因并保留原对象。绘画达到预算时不悄悄抛掉已有笔触。当前没有任意布尔蒙版树、局部曲线/HSL 或非破坏克隆修复，不能只通过加按钮声称具备。

### 美颜在顶层，但不虚构识别

“美颜”直接进入人物区域精修。用户先添加并定位一个人物区域，再调整柔化、锐化、曝光、明暗、饱和、冷暖与色偏；另一人物创建另一独立区域。区域可自由命名，名称不是模型识别结果。

这为多人分别处理建立了真实数据结构与渲染链路。自动人脸/皮肤/妆容识别、祛痘/瑕疵修复、五官和身形形变尚未接入。后续应接入带版本的分析结果、用户纠正蒙版、位移场和保护区，不用同一全局柔化滤镜冒充这些功能。

## 3. 自由构图与曲线

构图使用原图整数像素矩形。8 个边角与中心手柄都直接改变同一矩形；宽高、左/上边界可以精确调整到 1 像素。常见比例是快捷起点，选择后仍能自由改宽高。撤销恢复完整矩形；拖拽取消、指针丢失或失焦不应留下半次历史。

目前旋转为 0/90/180/270 度，另有两个输出轴镜像；任意角度、透视、内容感知扩图不是已实现的确定性构图工具。裁切宽高不受 AI 生成尺寸档案约束。要把任意裁切图作为 AI 参考时，则独立检查供应商输入规则并说明限制，不能反过来禁止用户本地保存合法裁切图。

RGB 主曲线及三个通道各有 2–16 点，支持任意上下形状、反相、添加、删除、精确坐标、键盘和预设。保持 x 严格递增，以确保每个输入亮度只有一个输出。点之间当前采用线性插值，界面不冒称是可任意扭转的贝塞尔曲面。手势绑定指针、素材身份和通道；旧图或旧通道的晚到取消事件不能回写新图。

## 4. 颜色连续、数值明确

颜色选择器提供连续 SV 平面、0–360° 色环和 RGB/HSV/HSL 数值。HEX 支持带 alpha 的颜色，快捷色和收藏仅用于减少输入。sRGB/RGBA8 是当前工作精度，色谱的 SVG/CSS 显示清晰不等于实现了 HDR、Display P3 或印刷 CMYK。

照片调色是实际像素运算，包括基础 13 项、输入/输出色阶、8 色段的连续 HSL 插值、三路色彩分级、纹理/清晰度、黑白混合、褪色、暗角和确定性颗粒。正负值的意义逐字段定义：曝光/色偏等以中性值向两侧变化，锐化和柔化是两种各有非负强度的算法，不把“负柔化”等同于无损恢复细节。

颜色范围选区按原始颜色确定，显示取色按已经调色的画面确定；二者在入口和读数中区分。对已调色的黄色点取“显示色”用于配色沟通，不能把这个黄色直接当作原图中红色像素的匹配条件。

直方图来源于当前真实预览像素，提供 RGB / R / G / B / Y′ 和线性/对数纵轴。端点百分比是该预览的编码值统计，不是相机 RAW 溢出判断。曲线页共享同一统计缓存，避免同一画面重复扫描。

## 5. 即时预览、动画与状态

连续拖动的渲染采用背压：主预览最多 1 个在途和 1 个最新待执行任务；比较/无裁切辅助预览也有界，过时结果根据源身份和配方键丢弃。松手提交一次完整历史，不为每个鼠标移动制造一个撤销步骤。比较结果未就绪时显示计算状态，不把当前处理图伪装为原图。

动效清单见 [MOTION.md](../apps/web/MOTION.md)。54个通用逻辑角色与6个编辑器专属角色分别定义响应式轨迹；多个DOM实例可复用同一角色。通用注册表指定进入/退出时长、延迟、位移、缩放、模糊与交互响应，专属CSS也显式配置桌面、平板、手机和短横屏的时长、延迟、位移/缩放与模糊。不同角色可共享实现机制，但不共用一个万能时长。图片、草图及其祖先保持像素安全，不对照片施加 UI 的高斯模糊；拖拽中立即响应。减少动态偏好关闭延迟、位移和模糊。加载反馈依据真实任务状态，不伪造百分比。

“即时调节”在本版是静态图片的实时预览，不是直播/摄像头视频处理。视频帧管线、实时人脸跟踪和直播编码尚未实现。

## 6. 组织、搜索与协作

个人和团队出现在同一导航中，空间权限和钱包彼此独立。素材可以按项目、日期与来源分组，并在实际空间/项目范围查询。加载更多使用服务器游标，不把当前已加载的一页误当作全部搜索结果。

元数据有四个层次：不可变图像字节；服务器创建时间；用户声明的拍摄时间/位置；版本化编辑配方。编辑标题/标签/拍摄时间/位置不改图片哈希，保存注释有自己的版本冲突检查。用户没有提供位置就保持为空，不推断住所、拍摄点或设备定位。默认不把位置写入下载文件。

项目还连接讨论、版本反馈、任务、文档和交付。当前协作通过权限、不可变修订、CAS 冲突和持久事件建立可靠基座；实时多人同参数自动合并与跨图自动依赖传播未实现。复制与参考授权具有不同语义，不能因界面统一而取消空间隔离。

## 7. AI 嵌入方式

草图和图片可以作为明确选择的参考；AI 生成结果是新的素材/作品，可再次打开精修。模型与参数由服务器能力描述驱动。图片模型没有开放的参数显示原因，不把界面截图里的所有选项无条件发送给任意模型。

调整建议读当前文字和数值配方，返回白名单内实际差异，由用户确认应用；它不具备未接入的看图识别人脸能力。生图/改图可以真实发送所选参考图。文字生成可带选定文档和父文案上下文。语音先录制/试听，再识别、审核、确认文字并填入对应任务，不自动把一句话变成多次收费调用。

没有模型、审核、账号或项目条件时显示真实缺项，不使用演示结果。本轮未向真实供应商账号发送付费模型请求，也未完成真实手机硬件、麦克风和大陆三网验收。账户权限、账单、输出质量和网络可达性不能由能力目录、测试替身或浏览器iframe布局检查推定。

## 8. 后续深度开发顺序

1. 原分辨率局部瓦片检查、硬件加速、持久蒙版资产与取消协议，先解决高像素交互成本。
2. 可替换的人脸/皮肤/妆容分析，分析版本与源图绑定，允许手动校正和多人物独立控制。
3. 位移场/修复笔/图层/文字矢量，保持旧配方重放、明确合成顺序和保护区。
4. 跨图引用依赖与批量配方，先给出影响预览、版本/权限校验，再允许传播。
5. 实时协作按对象和操作设计冲突策略；不把最后写入覆盖当作共同编辑。
6. 真实账户、短信、审核、声音设备、付费订单和跨运营商网络验收完成后再开放相应生产能力。

这些不是要求用户重新搭建基础模块：现有版本化配方、接口、权限、任务/账本和 UI 状态应继续复用。新增能力必须有真实数据流与回归，不以扩大按钮列表代替实现。
