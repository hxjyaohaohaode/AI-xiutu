## 统一风格，分别设计用途

颜色继续使用项目已有的浅色纸面、深色工作区和暖色强调语义。每个状态都从同一套主题变量取得背景、边线、文字和焦点色，不能在深色主题里遗留硬编码白色底部区域。图形尺寸与操作触点分别计算，桌面、平板、手机及短横屏分别限定布局。

共用原生 dialog 的焦点、关闭、异步确认和 inert 行为，视觉通过 14 个独立 profile 区分认证、账号、计费、危险操作、导出、绘图、命令、详情、协作、媒体、导航、设置、AI 和普通表单。每个 profile 的几何与运动都集中在同一 TypeScript 定义，CSS 和退出保留时长消费同一值，避免外壳提前消失或逐渐变成两套时间。

账号 tab、手机号步骤、验证码字段、异步提交、额度数字、权限错误、注销说明和退出确认使用独立的内容结构。复用的是有语义的底层行为，不以一个大卡片替换全部业务界面。

## 可读性和速度的取舍

- 输入、拖动、选择不等待装饰动画完成。方向切换可中断，旧回调不影响新状态。
- 表单、错误、价格 / 服务点、验证码和照片的模糊为 0；弹窗背景只使用 0–2px 的有限模糊。
- `ChoiceSelect` 只在展开时测量与监听；实际说明换行后重新计算位置，不使用固定行高推导。
- 账号与选择器保留键盘焦点，单独滚动真实列表 / 标签条，不调用会把整个工作区滚走的通用 `scrollIntoView`。
- 手机输入保持 16px，主要操作触点为 44px 级；图标保持可辨认比例。短横屏削减次级空白，不能隐藏关键确认动作。
- 支持系统减少动态效果；不为实现参考动画额外加载第三方动画库。

这些是实现参数与设计判断，不是实机性能数字。实际截图、浏览器场景、构建体积和 CI 结果由最终验收记录提供。

## 接口事实与后端交接

认证、真实 session、个人 / 团队空间、服务点和账本沿用现有接口。注册成功、重置成功、已退出等结论只来自通过校验的服务端回执或明确的只读会话核对。短信、登录或退出回执未知时不重复发送有副作用的请求。

在线购买、订单、退款、订阅取消、自助注销及注销后手机号重新注册没有当前可调用的完整服务端契约。因此页面提供可见、可解释的能力状态以及账本、导出、返回工作区、退出 / 登录的真实下一步；没有生成假金额、假订单或假注销完成页。待补契约详见 [账号接口对齐记录](account-contract-20261110.md)。

注册完成后的个人空间入口、访客登录 / 注册入口和账号中心已接入 App。后台会话读取、账号切换、团队成员刷新和退出使用同一会话范围保护。代码检查与接口模拟不能替代生产短信、支付供应商、真机软键盘或物理触控板验收，这些边界会保留在交付说明中。
