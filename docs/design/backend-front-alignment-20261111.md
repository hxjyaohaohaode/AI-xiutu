# 本轮前端与编辑能力对齐 · 2026-11-11

这份记录核对当前共享工作树的真实类型、注册目录、编译器、Worker 和前端调用，区分已有链路、本轮修复及后续接口需求。本轮已同步主分支 `2392944b98410e4983209334e0e10320540dfee2` 的精确编辑与场景测量变化；以下能力以这次已收到的源码为准。用户在另一本地后端工作区尚未推送的描述不等于已实现功能，也不能据此增加声称可用的算法按钮。

## 本次同步需要共同保留的接口

- `SelectionMaskV3` 的径向扩展由共享解析器、采样器、画布轮廓和数值控件共同消费；V2旧格式不冒充支持新字段。
- `EditorState.preview(next, quality)`、协作预览包装、Worker消息与画布帧质量标记一起更新；`'warp'` 保留完整编辑预览，常规 `'fast'` 继续使用自适应策略。
- 液化预算扩至128笔；超过64笔时还限制归一化半径平方和≤64。人物与手动笔触共用预算，不能按控制数或人物数重复放大。
- `AssistantBranchEvent.kind` 的三种新节点与 `dependsOn` 同步到前端图谱。沿用 `GET /v1/assistant-turns/:turnId/branches`，不新造平行请求协议；`propose_scene_balance` 是函数工具，不是新增公开HTTP端点。

这些条目说明源码与前端接线；合并前的截图、单测和完整测试快照不能自动覆盖本次新接口。最终类型检查、回归及私有HTTPS验收应关联合并后的提交另记。

## 公共目录需要进一步统一的项目

[`createBuiltinRegistry`](../../packages/contracts/src/catalog.ts) 中 `portrait.skin-segmentation`、`portrait.body-analysis`、`portrait.makeup-analysis` 仍为 `contract-only`；同时浏览器现有人像 Worker 已有具体 MediaPipe 分割/姿态路径。两者的命名范围需要后端明确：是泛化的未来端口，还是同一实际浏览器能力。当前不能直接把目录状态改成 available，因为模型资产、浏览器执行条件、分析来源和各项可用性仍要真实验证。

`GET /v1/editor-contract` 的数值元数据与公共模块目录不是执行授权。新增功能交接至少包含：稳定工具ID、实际实现状态、适用配方/算法版本、源坐标语义、正负/中性定义、范围/步长、所需目标/保护区、错误与取消状态、保存/预览/导出一致性、历史兼容和真实样本验收。前端随后可以按工具自身状态设计控件，而不是维护第二套猜测范围。

账号、付款和自助注销的独立后端缺口另见 [账号契约](account-contract-20261110.md)；本轮账号页面由单独工作单元对齐，不把编辑算法升级混作账户接口已完成。
