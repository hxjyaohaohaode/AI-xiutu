# 手机精修与选区变换 · 2026-11-11

## 依据与问题

本轮检查了当前源代码及已有的真实手机截图 `docs/verification/evidence/frontend-experience-20261111/studio-mobile-en.jpg`。旧截图中的照片位于上半屏，调节面板在一条滑条之前叠放了多个导航层；没有任何局部范围时仍出现“整张照片”选择；参数切换依赖反复打开选择器。贴底面板已有连续尺寸、最大化与折叠状态，但手机样式隐藏了折叠按钮，使“把空间还给照片”不够直接。

开始检查时，选区代码默认开启覆盖显示，用户调颜色时也持续看到红色蒙版；多边形只有逐点编辑，径向共享格式没有旋转字段。本轮随后同步主分支 `2392944`：V3/V4 径向蒙版增加真实 `rotationDegrees` 与 `shape`，共享解析器、采样、画布和数值控件一同支持旋转及椭圆/矩形/菱形；与本轮多边形整区移动、旋转和移动操作优化共同保留。

### 公开交互依据

- [W3C：Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements)：拖动以外也应有单指针操作途径。整区移动有数值输入，旋转有步长与方向按钮；画布手柄另有键盘微调。
- [W3C：Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) 与 [Target Size Enhanced](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)：可见图形不必和触达区域一样大。本轮手机选区手柄、主滑条和横向参数按钮使用 44 CSS px 触达尺寸；标题栏状态键在 44px 高的既有标题栏内使用 40px 高度。这里记录局部尺寸设计，不宣称整站通过 AA 或 AAA 审计。
- [Chrome：视口与屏幕键盘](https://developer.chrome.com/blog/viewport-resize-behavior)：可视视口和布局视口可能分别变化。工作区原有键盘可用高度计算现在也监听 `visualViewport.scroll`，避免可视区域平移后面板位置仍按旧坐标计算。

上述文档在本轮通过公开网页检索和正文读取，不能代替物理手机操作。Material 3 文档仅返回脚本加载页，没有把它计为已完成的视觉研究。

## 坐标、事务与性能

多边形的坐标存储仍是共享配方的归一化点。旋转先乘以原图宽、高，在源像素坐标中旋转，再除以对应尺寸；不会把非正方形照片上的选区剪切成另一种形状。旋转不添加新配方字段，也不改变羽化或反向选择。整个形状超出源边界时拒绝这次旋转，避免截断顶点造成形变。

画布仍使用原有坐标映射、配方解析、预览所有权和撤销/提交入口。新手柄加入原有指针取消、第二触点、失焦和来源身份保护。面板拖动的几何发布合并到每个动画帧，结束前刷出最后一个待发布位置；取消恢复原矩形，切换面板时丢弃旧回调。面板的移动动效继续按照实际位移和尺寸差计算，直接拖动不等待展示动画。

定位反馈只对覆盖层透明度动画，不对照片做模糊。减少动态偏好关闭这段动画，定位仍按时结束。新文案有简体中文、繁体中文和英文，集中于 `workspace/studio-copy.ts`，没有修改用户照片或用户文本。

## 验证与仍需确认的范围

### 实时预览质量恢复

`render.worker.ts` 原来的实时预算只降不升：一次超过42ms的工作就把131,072像素减半，最低32,768，直到重导入才恢复。新 [`InteractivePreviewPolicy`](../../apps/web/src/editor/interactive-preview-policy.ts) 按实际改变的数据分类，控制普通快通道的显示栅格预算。同步 `2392944` 后，显式 `previewQuality:'warp'` 的手动液化走完整编辑预览，绕过下表的降采样策略：

| 操作                                       | 起始像素 | 最低像素 | 恢复上限 |
| ------------------------------------------ | -------: | -------: | -------: |
| 曝光、色彩、曲线                           |  131,072 |   32,768 |  131,072 |
| 锐化、柔化、纹理、降噪等细节               |  131,072 |   65,536 |  131,072 |
| 构图、精细几何与四角变换                   |  131,072 |  131,072 |  262,144 |
| 液化变化的普通快通道（未显式请求精细通道） |  131,072 |   65,536 |  262,144 |
| 选区、绘制、合成、局部修复                 |  131,072 |   65,536 |  262,144 |

切换操作类别、新来源、完成上一帧后空闲800ms，恢复该类别起始预算。连续两帧超过48ms，或一帧超过96ms，降低一级；连续四帧低于18ms且距上次调整至少240ms，才恢复一级。时间阈值是集中可调的策略参数，不是设备帧率承诺。慢帧的计算时间不计作空闲，旧来源/旧帧的迟到耗时不改变新状态。

普通快通道保留最多262,144像素的源栅格，每个RGBA8来源约1MiB，恢复时从该源栅格重算。普通颜色初始预算没有提高；空间操作在连续便宜的帧后尝试更清晰的一档。精细液化另保留最多4,194,304像素的完整编辑预览及相应合成素材，并由 `WarpPreviewCache` 缓存液化前的不可变中间结果；这些缓冲额外占用内存，4MP RGBA8单幅约16MiB，不能继续把实时Worker总内存描述为只有1MiB。

新 V4 手动液化和八项新面部精细控制采用 `flow-v2` 与 `bounded-cubic-v1`：合成逆位移后只重采样一次，在线性光/预乘alpha下执行有界三次采样。旧笔触保留原算法；新算法不静默替换已保存作品。导出继续从完整编辑源图走参考渲染，完整预览并不等同任意原尺寸的1:1实时编辑。复杂配方在高负载移动设备上的时延、内存和极值质量仍需实测，不能宣称所有模糊与延迟已经解决。

新策略和真实 Worker 针对性回归另覆盖：连续慢/快帧、防抖、跨工具/空闲/来源恢复、非停顿的长帧、预算上下限、实际源栅格恢复以及最终导出与参考引擎逐字节一致。时钟在策略整合测试中明确注入，像素、Worker处理器和传输均为真实实现；这些单测不作为物理设备性能证据。现有 `interactive-preview.browser.mjs` 保留真实DOM拖动、画布绘制和源像素一致性断言，新增报告实际实时栅格的最小/最大像素数，用于CI对比清晰度与时延。

### HTTPS 预览反馈后的修正

主工作单元随后提供了真实私有预览截图 `docs/verification/evidence/frontend-immersive-20261111/review-mobile-polygon.jpg`（390×844）与 `local-zh-CN.jpg`（1440×960）。检查确认移动照片区域、实际多边形顶点/移动/旋转柄和状态键均已呈现；同时发现旋转后整体中心的范围端点直接显示了长浮点尾数，以及桌面滚动位置带入手机后切掉当前参数标题。

修正后的端点按步长允许的显示精度和当前语言格式呈现，例如 `0.28462 / 0.71538`；原生输入 `min/max/value`、精确编辑草稿和配方仍保留完整数学值。数字格式器按语言/精度复用。切换工具仅重置检查器滚动位置；在手机/平板/桌面布局类别之间切换时也重置检查器滚动，普通调参、拖动和同类别键盘高度变化不触发。

这次反馈修正的参数架、范围手势、三语和工作区几何最小回归在合并 `2392944` 前 **41/41 通过**，当时Web typecheck、所属文件格式和差异空白检查通过。新三语断言同时检查短显示、完整原生数学值和零编辑回调。修正后浏览器截图由主工作单元继续采集，原问题截图保留作审阅证据；合并后的复验结果另记。
