## Agent 两个候选的真实计算

`agent-night.webp` 是生成的源照片。两个候选不依赖 CSS 滤镜冒充编辑结果，而是使用项目导出的 `createRecipeV4` 与 `renderRecipeV4` 计算真实像素。制作脚本为 `artifacts/render-agent-candidates-r3.mts`。

流程：将源 WebP 解码、缩小到 768 × 512、补齐 RGBA；从默认 V4 配方创建两个独立配方；修改曝光、阴影和高光；以 `maxPixels: 400000` 执行渲染；输出 768 × 512 WebP，`quality: 90, effort: 6`。源照片本身不被覆写。

| 文件                     |  曝光 | 阴影 | 高光 | 其他参数     |
| ------------------------ | ----: | ---: | ---: | ------------ |
| `agent-candidate-0.webp` | +0.08 |   +5 |   −5 | 默认 V4 配方 |
| `agent-candidate-1.webp` | +0.20 |  +14 |  −10 | 默认 V4 配方 |

核心制作代码如下；相对路径以仓库根目录为工作目录：

```ts
import sharp from 'sharp';
import { createRecipeV4, renderRecipeV4 } from './packages/editor/src/index.ts';

const source = await sharp('apps/web/public/about/agent-night.webp')
  .resize({ width: 768 })
  .ensureAlpha()
  .raw()
  .toBuffer({ resolveWithObject: true });

for (let index = 0; index < 2; index++) {
  const recipe = createRecipeV4();
  Object.assign(
    recipe.adjustments,
    index === 0
      ? { exposure: 0.08, shadows: 5, highlights: -5 }
      : { exposure: 0.2, shadows: 14, highlights: -10 },
  );
  const output = renderRecipeV4(
    {
      width: source.info.width,
      height: source.info.height,
      data: new Uint8ClampedArray(source.data),
    },
    recipe,
    { maxPixels: 400000 },
  );
  await sharp(Buffer.from(output.data), {
    raw: { width: output.width, height: output.height, channels: 4 },
  })
    .webp({ quality: 90, effort: 6 })
    .toFile(`apps/web/public/about/agent-candidate-${index}.webp`);
}
```

因此可称两个展示候选为“实际编辑引擎渲染结果”。生成配方的是上述固定制作步骤，不是本次真实在线 Agent 会话；本记录不把候选的生成等同于 Agent 已完成模型调用、收费事务或版本保存。

载入策略按源码核查：

- 只有首屏 `hero-editorial` 在 About 使用 `eager` 与 `fetchPriority="high"`；其他章节图片保持原生 `loading="lazy"` 和 `decoding="async"`。
- 图片先保留确定比例，待加载骨架与失败重试都在原框内，避免因资源迟到而将章节挤塌。
- 功能截图由展开状态决定是否挂载。设备截图沿用统一懒加载组件；当前语言切换时再选择对应截图资源。
- 页面按需载入及浏览器缓存可以避免将目录总量等同于每次首屏下载量，但原生 lazy 的提前获取距离由浏览器决定。这里没有用源码推断实际弱网请求瀑布。
- 静态图片的部署体积、解码成本、代码分块体积和实时预览预算是不同指标。此处没有运行新一轮生产构建或网络性能测试，不声明 LCP、CLS、FPS 或低端手机性能已达标。
