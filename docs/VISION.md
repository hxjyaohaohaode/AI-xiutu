# 人物识别、手工标注与真实可用性

本页说明人像模块的实际依赖、失败行为、扩展入口和质量边界。人物识别提供关键点和分割结果；美肤、五官、美体、化妆控制随后编译成同一个编辑引擎的局部调节、绘制和位移节点。识别成功和成片质量分别验收。

## 1. 同源模型准备

```sh
npm ci
npm run vision:prepare
```

脚本从 Google 和 OpenCV 的官方来源下载固定版本的模型，逐文件校验 SHA-256，复制锁文件指定的 Tasks Vision 与 ONNX Runtime WebAssembly 资源，并生成 `apps/web/public/vision/manifest.json`。基础识别的六个模型约 28 MB，另有抠图模型和 WebAssembly 运行时。它们按需从网站自己的 `/vision/` 加载，自动识别时照片留在浏览器。

| 资源                        | 用途                         | 不是它能保证的能力                                     |
| --------------------------- | ---------------------------- | ------------------------------------------------------ |
| Face Landmarker             | 面部关键点、五官定位         | 身份认证、遮挡后精确补全、任意角度人脸可靠识别         |
| BlazeFace Full Range        | 为远景小脸提供二次定位窗口   | 在缺少足够像素时确认五官、修饰被遮挡的部位             |
| YuNet                       | 补充遗漏的小脸和暗光人脸候选 | 代替稠密点位复核，或判断任意画面是否为海报             |
| Pose Landmarker Lite        | 身体关键点、可见度与人物分割 | 多人拥挤、被遮挡关节、极端姿态的产品级美体质量保证     |
| Selfie Multiclass Segmenter | 皮肤、头发、衣物、背景等类别 | 单像素准确的商业级头发抠图、所有肤色与光照的无偏误分割 |
| Hair Segmenter              | 近景发顶、发际线与遮挡证据   | 找回被刘海遮住的发根或重建缺失的发丝                   |

MediaPipe 模型为 Apache 2.0，YuNet 为 MIT。许可副本及来源见 [`third-party`](../third-party/NOTICE.md)，在产品中再分发时随同保留。

## 2. 浏览器运行条件与当前实测边界

Web Worker 中需要 OffscreenCanvas、WebAssembly 和可用的 WebGL 2 图像输入路径。即便推理委托选择 CPU，当前 Tasks Vision 的 Web 图像输入仍会经过图形上下文，不能据此承诺完全不依赖 WebGL。Worker 在加载模型前检查图形条件，失败会明确提示用户；不会生成虚构的人脸框或悄悄套用默认五官位置。

本轮云端 Chrome 实测：模型曾成功载入，但推理图像输入出现 `activeTexture` 上下文错误。因此此环境的“浏览器自动识别成功”目前不能作为验收结论。已加入前置能力检测、超时、取消与可读错误。支持 WebGL 2 的电脑和手机仍需正式设备矩阵验收。原生 Python CPU 推理与浏览器 JavaScript 推理属于不同运行路径，测试报告会分别列出。

操作中切换图片会取消旧分析。分析超时为 60 秒，用户可主动取消。只对与当前完整 RGBA 像素、尺寸及色彩基准完全一致的结果开放人像控件，避免把上一张照片的人脸位置套到下一张。

## 3. 人物标注接入

美颜面板的“人物标注与分析接入”支持导入、导出经过协议校验的分析 JSON，可承接自己的识别服务、桌面推理或人工校正工具。导入结果明确显示为导入标注，不显示为本机自动识别成功。

导入限制和约束：

- JSON 文件不超过 2 MiB；禁止执行代码、加载远程图片或模型。
- schema、提供方、算法版本、点位范围、蒙版预算均须通过 `@ai-xiutu/portrait` 校验。
- 标注的 `frame`（`SourceFrame` 类型）绑定当前尺寸和 `SHA-256(UTF-8("宽x高:srgb-rgba8:") + 原始 RGBA 字节)`。
- 浏览器输出 `provider: mediapipe` 和 `algorithmVersion: portrait-v5-scene`，同时接受此前的 v1 至 v4 标注格式。已有配方继续使用保存当时的算子和参数。
- 原图旋转归一化或色彩解码不同会产生不同摘要；应对识别与浏览器导入使用同一份已规范化的 PNG。

源文件和标准入口见 [`packages/portrait`](../packages/portrait/README.md) 与 [`EXTENSIONS.md`](EXTENSIONS.md)。产品不内置测试照片或预生成假标注。

## 4. 自动调节与手工精修共存

自动参数以人物为单位管理，多个目标各自保存参数和化妆颜色。缺少所需关键点、皮肤区域或关节时对应工具应关闭并解释原因。不能用“识别到一个人”推导出所有美体和五官工具都可靠。

“转为手工图层”会把选中人物的自动局部、绘制与液化节点一起交给通用编辑器，保留像素和来源追溯；之后可改蒙版、颜色、混合模式、笔迹与位移。再次自动调节会建立新的自动节点，避免重写已经手工编辑的节点。如果绕过此入口手改自动节点，模块的完整性检查会拒绝后续破坏性重建，并要求先完成转换。

磨皮、纹理弱化和局部肤色调整已有受蒙版约束的基础算法；手工祛瑕使用明确的仿制源。自动检测痘斑、单条皱纹并进行纹理重建尚未实现，不能把普通模糊或仿制命名为这些自动能力。复杂皮肤重建、遮挡修补和商业级人像细节还需要专项模型与真实样本质量评测。五官与身体调整使用可回退的有限位移场，不声称具备商业软件全部算法的等效质量。

## 5. 后续必须补齐的设备与质量验证

验收应覆盖桌面 Chrome/Edge/Safari、Android Chrome、iOS Safari、平板横竖屏；至少包含不同光照、肤色、年龄外观、侧脸、遮挡、眼镜、多人重叠、全身与半身。逐项评估关键点定位、蒙版边缘、背景保护、面部身份特征保持、纹理损失、画面变形、峰值内存与耗时。

不能把有限照片的成功率写成所有图片的准确率，也不能把数值单元测试写成真实设备或审美效果测试。真实记录见 [`VERIFICATION.md`](VERIFICATION.md)。
